A desktop client for HTTP, GraphQL, gRPC and socket APIs

PostSonde sends and tests requests, and runs local servers for the clients you are testing. There is no account and no cloud. It connects only when you send something, and a project is a folder of plain JSON files.

Build it from source PostSonde on GitHub

No release yet. The first packages for Linux, macOS and Windows are being prepared.

Requests of every kind

Each kind of request has an editor of its own. All of them share the environments, variables, auth, proxy settings and history.

HTTPREST and plain HTTP
Any method, parameters, headers, and JSON, XML, form, multipart or file bodies. Filter the response with JSONPath or XPath, and see each phase of the exchange in its timeline.
GQLGraphQL
A schema from introspection or an SDL file drives validation, autocomplete and a docs explorer. Subscriptions run over WebSocket or SSE.
GRPCgRPC
Services from .proto files or server reflection. Unary calls and all three kinds of streaming, with messages edited as JSON.
WSWebSocket
Text and binary messages, saved messages to send again, and a log of both directions.
SIOSocket.IO
Events with acknowledgements, over WebSocket or long-polling, for servers from v2 to v4.
SSEServer-Sent Events
Events as they arrive, with optional reconnects that resume from the last event ID.
TCPRaw TCP
Plain or TLS connections, messages split by line or by a length prefix, and input as text or hex.
UDPUDP datagrams
Datagrams to any host, sent directly or through a SOCKS5 proxy.

Servers to test against

PostSonde can also take the other end. A mock HTTP server answers from routes you write, generate from an OpenAPI document or copy from a response you received. A webhook receiver keeps every request that arrives, to inspect and send again, and an echo server answers each request with a description of it. For clients of other protocols there are WebSocket, Socket.IO, SSE, TCP, UDP, gRPC and GraphQL servers. They all listen on 127.0.0.1 unless you choose another address.

A project is a folder of files

Every request is one JSON file, and every folder is a directory with a _folder.json, next to one file per environment. The format is documented field by field, so the files can be read, reviewed and edited by hand, and kept in git next to the code they test.

History, cookies, OAuth tokens and secret values never go into the project folder. They stay in PostSonde's data directory on your computer, which you can encrypt with a master password.

It connects when you send

PostSonde has no telemetry, no crash reports, no update checks and no account. Its interface is built into the app, with no web fonts or remote images, and a Content Security Policy blocks anything else. These are the connections it makes:

What goes outWhen
Your requests and connectionsWhen you send or connect, run a folder, or replay a request that a local webhook server received
DNS lookups of the hosts in themWhen the request goes out. Through a SOCKS5h or HTTP proxy, the proxy resolves the name instead.
OAuth 2.0 token requestsWhen a send needs a token, or when you ask for a new one
GraphQL schema introspectionWhen you fetch or refresh a schema
A proxy connection testWhen you click Test in the proxy settings

Local servers only listen; they never open connections of their own. PRIVACY.md has the complete list, and how to check it yourself with an outbound firewall or strace.

Where it stands

PostSonde has not had a release yet. What this site describes is in the code, and you can build it from source today. The first packages are being prepared.

  • Linux

    A GTK 4 build, and a GTK 3 build for Ubuntu 22.04 and Debian 12, for x86-64 and ARM64.

    Developed and tested on Fedora 44 with KDE Plasma

  • macOS 13 or later

    One app for Apple silicon and Intel Macs, in a disk image.

    Builds, but not tried on a real Mac yet

  • Windows 10 and 11

    An installer for x64 and one for ARM64. No administrator rights needed.

    Builds, but not tried on a real PC yet

If you try it on a Mac or a Windows PC, a note in the issue tracker helps, whether it works or not.
