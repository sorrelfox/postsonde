# Frontend

The UI is React + TypeScript (strict), built with Vite, in `frontend/`. It talks to the Go core only through the Wails bindings.

## Layout

```
frontend/
  index.html, vite.config.ts, tsconfig.json, package.json
  csp.json          the Content Security Policy (docs/privacy.md)
  public/           copied into dist/ as is: theme-init.js (theme before first paint)
  scripts/          build tooling: check-dist.mjs, the no-remote-URL check (docs/privacy.md)
  bindings/         generated Wails bindings, not committed (see docs/bindings.md)
  dist/             Vite build output, embedded by assets.go
  src/
    main.tsx        entry: Wails runtime, global CSS, renders <App/>
    App.tsx         root: providers, then the app shell
    components/     React components, one folder per area
      shell/        title bar, icon rail, status bar, pane layout and splitters
      workspace/    welcome screen and the gate between it and the shell
      environments/ environments sidebar panel, title-bar switcher
      history/      History sidebar view: search, filters, restore, clear (NAV-02, NAV-03, docs/history.md#the-history-panel)
      tree/         collection tree sidebar: virtualized, keyboard tree, badges
      tabs/         tab bar, active tab's panel, tab key bindings
      editor/       request pane and the CodeMirror wrappers
      messagelog/   the shared message log of streaming connections and the message composer, used by the TCP, WebSocket and Socket.IO editors, the gRPC and SSE response panes and the WebSocket server
      servers/      Servers sidebar view, server details and traffic log (docs/servers.md)
      settings/     the settings screen behind the rail's gear (docs/settings.md)
      cookies/      the cookie manager dialog and its status bar button (CK-02, docs/cookies.md)
      console/      the console panel and its status bar button (DBG-06; see Console)
      response/     response pane
      common/       small shared controls (icons, context menu, dialog, toasts, tooltip, tab list keys, log copy and save: LogActions)
    commands/       user intents: binding calls and multi-store updates
    stores/         state: store primitive, one module per store, provider and hooks
    lib/            framework-free helpers: binding wrappers, errors, events,
                    shortcuts/ (the keyboard shortcut registry and chords)
    styles/         tokens.css, base.css, fonts.css
    i18n/           localization (UI-10): t(), useT(), the English catalogue in en/<namespace>.ts,
                    the pseudo-locale, the allowlist of the hard-coded string check (see Localization)
    assets/         fonts/, icons/
```

Folders appear when their first file lands. `components/shell/` and `components/common/` come with the app shell.

Changes from the baseline layout:

- **`commands/` is new.** Commands need both the stores and the binding wrappers. Keeping them out of `stores/` keeps reducers pure and `stores/` free of I/O. Keeping them out of `lib/` keeps `lib/` independent of React and of the stores.
- **`response/` is split from `editor/`.** The response pane (viewer, headers, timings) grows separately from the request editor.

## Dependency direction

```
components  ──▶  commands  ──▶  lib  ──▶  bindings, @wailsio/runtime
     │               │
     └──────▶  stores  ◀──┘
```

- `stores/` imports only React and its own files. Never `lib/`, `commands/`, bindings or components.
- `lib/` has no React and no stores. Only `lib/` imports the generated bindings (see docs/bindings.md).
- `commands/` imports `stores/` and `lib/`.
- `components/` import `stores/` (hooks, types, selectors) and `commands/`. They may use pure helpers from `lib/` (formatting, error text) but never call bindings directly.
- Import the state layer through its barrel, `stores` (`import { useTabs } from "../../stores"`), not the files inside it.
- `i18n/` imports nothing of the app. `lib/`, `commands/` and components may import `i18n` (the barrel, no React: `t`, formatting, the locale); components also `i18n/react` (`useT`, `useLocale`, `Trans`). Stores keep message keys, not text. See [Localization](#localization).

Eight stores, each a module in `frontend/src/stores/`:

| `drafts` | `byId`: `{ request, dirty, revision }` per open request; `dirty` until Go confirms the edit on disk. `subTabs`: the editor sub-tab shown per open request (UI state, never saved). `bodyStash`: bodies the body editor switched away from, per request and mode (never saved). `conflicts`: drafts in conflict with their file (STO-05) and `otherWindow`, those of them in conflict with another window's edit (APP-06) | `open`, `edit`, `markSaved`, `rename`, `setSubTab`, `stashBody`, `replace`, `conflict` (with `source`), `resolve`, `discard` |

| `settings` | `theme` (`dark`, `light`, `system`), `customTheme` (a theme file name or `""`, UI-05), `sidebarCollapsed`, `splitRatio`, `defaultTimeoutMs` (0: none), `verifyTls`, `maxResponseBodyMb` (HTTP-37), `responsePosition` (`beside`, `below`), `splitRatioBelow`, the editor settings `editorFontFamily`, `editorFontSize`, `editorTabSize`, `editorWordWrap`, `editorLineNumbers`, `editorMatchBrackets`, `shortcuts` (custom chords by shortcut id, UI-07; `{}` for none) | `load`, `setTheme`, `setCustomTheme`, `setSidebarCollapsed`, `toggleSidebar`, `setSplitRatio` (of the layout in effect, or of `position`) |

| `environments` | `status`, `workspaceKey`, environment `ids` (sorted by name) and `byId`, `activeId`, `selectedId` (panel), `problems`, `readOnly` ([environments.md](environments.md)) | `loading`, `loaded`, `failed`, `clear`, `put`, `remove`, `setActive`, `select` |

Action types are namespaced: `"tabs/open"`, `"drafts/markSaved"`.

### Reading state in a component

Select the smallest value the component needs. It re-renders only when that value changes.

```tsx
const name = useCollection((s) => s.nodes[id]?.name);
const isDirty = useDrafts((s) => selectIsDirty(s, id));
const order = useTabs((s) => s.order);                     // same array until it changes
const dirtyIds = useDrafts(selectDirtyIds, shallowEqual);  // new array each call: pass shallowEqual
```

- Never select the whole state (`useTabs((s) => s)`): the component then re-renders on every change.
- A selector that builds a new array or object needs `shallowEqual` (or its own equality).
- An event handler that needs the current state reads `stores.<store>.getState()` instead of subscribing.

### Writing state

- One store, no I/O: dispatch directly.
  ```tsx
  const { tabs } = useStores();
  <button onClick={() => tabs.dispatch({ type: "tabs/activate", id })} />
  ```
- More than one store, or anything that calls Go: call a command.
  ```tsx
  const stores = useStores();
  <TreeRow onOpen={() => openRequest(stores, id)} />
  ```
- Editing a request: `editRequest(stores, id, patch)` or the `useAutoSave(id)` hook (`commands/`). Edits are auto-saved; there is no save command ([collection.md](collection.md#auto-save)).
- A long-running Go operation that streams events: use `useOperation` from `commands/useOperation.ts` (a hook that calls Go, so it lives in `commands/`, not `stores/`). See [events.md](events.md).

### Rules for reducers

- Pure: no I/O, no bindings, no `Date.now()` or random values (put them in the action).
- Immutable updates. Return the **same** state object when nothing changed; the store then notifies nobody.
- Plain data only: records keyed by id, id arrays, `Record<Id, true>` for sets. No `Set`, `Map` or class instances.
- Normalized: store each node once, by id, and refer to it by id.
- Unknown or invalid input (an id that does not exist, a theme that is not allowed) leaves the state unchanged.

### Side effects

- Binding calls, file I/O and multi-store workflows go in `commands/`. A command is a plain function whose first argument is `stores`. It calls the `lib/` binding wrappers and dispatches the results.
- Subscriptions to Go events are set up once near the root and dispatch into stores.
- Components do not call bindings and do not dispatch to several stores in one handler.

### Local state

Use `useState` for state no other component reads: hover, an open menu, a text field before it is committed, a splitter drag in progress.

CodeMirror owns the text of an open editor. The editor builds its state from the draft when its tab opens or becomes active (or takes back the state it kept for that request, see [Undo and redo](#undo-and-redo)), and dispatches `drafts/edit` from its change listener. It does not take the draft text back as a controlled value on every keystroke.

### Tests

Reducers and selectors are plain functions: test them as `(state, action) => state` with Vitest, without React or a DOM (`stores/settings.test.ts`, `tabs.test.ts`, `collection.test.ts`). `StoreProvider` takes a `stores` prop (`createStores({ tabs: … })`) to seed component tests.

Tests may import the real `@wailsio/runtime` (`lib/errors.test.ts` runs real `Call`s against a stubbed `fetch`). Importing it starts a 50ms polling `setInterval` in the runtime's drag module; when a file ended before its first tick, the tick ran after Vitest tore jsdom down and failed the run with "window is not defined", though every test passed. `src/test/setup.ts` tracks the intervals a test file starts and clears the ones still running in `afterAll`, so a leftover interval can't outlive the file's environment.

## App shell

`components/shell/AppShell` is the window frame (UI-01): the title bar on top, then the icon rail, the collapsible sidebar and the main column (tab bar, request and response panes, status bar). Features plug in through its props instead of editing the shell:

| Prop | Renders in | Default |
|---|---|---|
| `tabBar` | the 40px row above the panes | empty |
| `request`, `response` | the left and right panes. Content fills the pane (`flex: 1; min-height: 0`) and scrolls itself. | token preview, empty state |
| `statusStart`, `statusEnd` | the left and right of the status bar | "Ready", version placeholder |
| `projectName`, `projectPath` | the title bar: the name, with the path as tooltip (the path alone without a name), while no project is open in the workspace store; with one open the title bar shows the project switcher instead | placeholder path |
| `onCloseProject` | a close button next to the project in the title bar | no button |

- **Project switcher (STO-06):** with a project open, the title bar shows `components/workspace/WorkspaceMenu`: the project's name and a chevron, which opens a `ContextMenu` with the other recent projects (at most 10; a missing folder is listed as "(not found)" and disabled), Open folder…, New project… (the folder dialog, then a small dialog for the name), Reveal in Finder ("Show in file manager" elsewhere), Manage recent projects… (opens the settings screen, whose General page lists them all) and Close project. Choosing a project calls `openWorkspaceAt`, which saves the open project's state first (see Workspace switching). Failures show as a toast; opening a folder that is not a project offers "Create project here". `ContextMenu` items can take `separatorBefore` and `title` (tooltip) for this.

- **Sidebar:** `settings.sidebarCollapsed`, toggled by the rail button and ⌘B (Ctrl+B on Windows and Linux). The active rail view is local state in `AppShell`.
- **Focus mode** (UI-09): ⇧⌘↩ (Ctrl+Shift+Enter, `view.focusMode`), or the command palette, hides the icon rail, the sidebar and the console panel so the tab bar, the request and the response fill the window; see [Focus mode](#focus-mode).
- **Command palette** (NAV-05): `AppShell` mounts `CommandPalette`; ⇧⌘P (Ctrl+Shift+P) opens it. See [Command palette](#command-palette).
- **Settings screen:** the rail's gear (or ⌘,) shows `components/settings/SettingsScreen` in place of the sidebar and the main column, which stay mounted but hidden so open editors keep their state. The gear again, a view button or the sidebar toggle go back. Whether it shows is local state in `AppShell`. See [settings.md](settings.md#the-settings-screen).
- **Shortcuts:** `AppShell` runs the global keyboard shortcuts (`useGlobalShortcuts`) and renders the shortcut help, so shortcuts work while a project is open, not on the welcome screen (see Keyboard shortcuts).
- **Dialogs and toasts:** `AppShell` mounts `ConfirmHost` (for `confirm()`), `PromptHost` (for `askPrompts()`, DYN-07) and, inside the main column, `ToastHost` (for `showToast()`), so they work while a project is open (see Dialogs and toasts).
- **Root:** `App` calls `useThemeSync` and `useSettingsPersistence`, then renders `components/workspace/WorkspaceGate`: an empty frame while loading, the welcome screen when no project is open, and `AppShell` for the open project ([workspace.md](workspace.md)).
- **Theme:** `useThemeSync` (called by `App`) runs `applyTheme` whenever `settings.theme` changes. `App` seeds `settings.theme` from `storedThemePreference()`, the first-paint cache, until the settings file has loaded (see Persistence and [Themes](#themes)).
- **Split:** `WorkArea` puts the panes in a `components/common/SplitPane`. `settings.responsePosition` (UI-02, General → Response position) picks the layout: `beside` (side by side, bound to `settings.splitRatio`, each pane at least 240px wide) or `below` (stacked, bound to `settings.splitRatioBelow`, each pane at least 140px high), while there is room for both. Each layout keeps its own split. Switching changes only the SplitPane's orientation, so the panes and their editors stay mounted. A drag or key press commits through `commitSplitRatio` (see Persistence).
- **Icons:** `components/common/icons.tsx`, inline SVG drawn with `currentColor`. No icon font, nothing remote.

### SplitPane

`<SplitPane orientation ratio onRatioChange onRatioCommit minStart minEnd minRatio maxRatio defaultRatio label>{[first, second]}</SplitPane>` is a controlled two-pane split. `orientation="horizontal"` puts the panes side by side; `"vertical"` stacks them. `minStart`/`minEnd` are px, checked against the container size measured with `ResizeObserver`, so resizing the window re-clamps the split. The stored ratio is kept, and the shown split is clamped.

- **Handle:** a focusable `role="separator"` with `aria-orientation`, `aria-valuenow`/`min`/`max` in percent and `aria-controls` pointing at the first pane.
- **Keyboard:** the Left and Right arrows (Up and Down when stacked) move it 2%, 10% with Shift. Home and End jump to the limits. Enter or a double-click resets to `defaultRatio` (50%).
- **Drag:** pointer capture. Pane sizes come from the `--split-ratio` CSS variable, written once per animation frame, so nothing re-renders during a drag. `onRatioChange` fires per frame and `onRatioCommit` once, on pointerup. Cancelling the pointer reverts the drag.

### KeyValueTable

`components/common/KeyValueTable` is the one key/value editor for params, headers, form fields, variables and metadata. `<KeyValueTable label rows onChange showDescription readOnly placeholders autoAppend renderValue isValueMasked valueActions suggest suggestLabels createId fixedKeys bulkEdit />`:

- **Controlled.** `rows` is `KeyValueRow[]` (`id`, `enabled`, `key`, `value`, `description`); `onChange` gets the whole next array. Row ids are stable across edits; `createKeyValueRow(init)` builds a row with a fresh id (`newKeyValueRowId`).
- **Columns:** enable toggle, key, value, description (hide with `showDescription={false}`), delete. `readOnly` (or no `onChange`) drops editing, the delete column and the empty row; cells stay focusable.
- **Adding:** with `autoAppend` (default) an empty row sits at the end and typing into it adds a row, keeping focus. With `autoAppend={false}` an "Add row" button is shown instead.
- **`fixedKeys`** (the path variables table): the rows are given. Keys are read-only; there is no toggle, empty row, Add row button, insert or delete (the shortcuts do nothing). The toggle and delete columns stay, empty, so the columns line up with a table above.
- **`renderValue(value, row)`** draws the value cell's text (e.g. `{{var}}` highlighting). The input stays the editor: its text is transparent and the rendered text sits underneath. Inside a `TemplateVariablesProvider` (a request's editor), value cells containing `{{` are drawn this way by default with `TemplateText`: each reference a chip, red when it does not resolve, and the cell's `title` lists each reference's value and scope (see Template variables).
- **`isValueMasked(row)`** makes a row's value a password field (secret variables); a masked value is not passed to `renderValue`. **`valueActions(row, index)`** adds small controls at the end of a row's value cell (the environments panel's local value, secret and show-value buttons); they are in the Tab order, not the arrow-key grid.
- **Keyboard (ARIA grid):** Up/Down change row in the same column; Left/Right change cell (in a text field only with the caret at its start or end). Tab moves through the text fields and then out of the table; toggles and delete buttons are reached with the arrows. Space toggles the row. ⌘Enter (Ctrl+Enter) inserts a row below; ⌘⇧Backspace or ⌘⇧Delete (Ctrl+Shift+Backspace or Delete) deletes the row. Both chords are the registry's `table.insertRow` and `table.deleteRow`; an editable table is marked `data-shortcut-scope="table"`, so ⌘Enter adds a row there instead of sending the request.

- **`suggest`** (`{ key?, value?, description? }`, each `(text, row, column) => Suggestion[]`) gives a text column an autocomplete popup (see Suggestions); `suggestLabels` names each column's list. `row` is the row as it is with `text` (for the empty row, the row it would become), so value suggestions can depend on the row's key. Editable tables only. Cells with suggestions are `role="combobox"` instead of text boxes.

- **`bulkEdit`** (HTTP-08) adds a **Bulk edit** switch (`aria-pressed`) right-aligned above the table; not with `fixedKeys`. On, the grid is replaced by a monospace textarea ("<label>, bulk edit") holding one `key: value` line per row (`components/common/keyValueBulk.ts`): a disabled row is written `// key: value` and read back from a line starting with `//` or `#`; the key runs to the first `:` (trimmed), the value is the rest without the one space after the colon; a line without a colon is a key with an empty value; blank lines are skipped. Descriptions are not written: `parseBulkText` gives each parsed row the id and description of the first unused row with the same key, so an unedited round trip returns the same rows (ids, descriptions, disabled rows, duplicates) and edited rows keep theirs. The text is applied as **one** `onChange` when it loses focus and when the textarea unmounts (the switch back, which keeps focus in the text on mousedown, or leaving the sub-tab); an unedited text applies nothing, so undo takes a bulk edit back in one step. Rows changed from outside while the text is not focused (an undo, the URL's query) replace the text. Read-only tables show the text read-only. The switch is on the Params, Headers and Form fields tables of the HTTP editor, the GraphQL and WebSocket headers (and WebSocket params), folder headers and gRPC metadata; not on path variables, multipart parts (file parts have no text form) or variables (secrets would show).

`components/editor/KeyValuePreview` shows it with sample params and headers in the skeleton.

### Suggestions

`components/common/Autocomplete` is the autocomplete popup for text fields: `useAutocomplete({ label, onAccept })` returns `show(target, items)`, `close()`, `onKeyDown(e)`, `comboboxProps(owner)` and the `popup` to render. The caller decides when to show what; `KeyValueTable` shows its column's suggestions on every edit of a cell and on ⌃Space or ⌥↓ (Ctrl+Space or Alt+Down, registry `table.suggest`).

- **Items** are `Suggestion`s (`lib/suggest.ts`): `value` (the field's whole text after accepting), optional `label` (shown instead of `value`), `detail` (dimmed description) and `note` (a hint: an info mark with the note as tooltip, and the highlighted item's note under the list). At most 8 (`MAX_SUGGESTIONS`).
- **Filtering** (`filterByMatch`, `matchRank`), case-insensitive, best first, list order within a rank: equal, prefix, prefix of a later word (after `-` `_` `/` `.` `+` `;` `=` or a space: `enc` finds `Accept-Encoding`), substring, then the characters in order starting with the first (`ctype` finds `Content-Type`).
- **When it shows:** typing opens it with the first item highlighted; an empty field closes it (⌃Space still opens it); no items, or a single item equal to the text, keeps it closed.
- **ARIA combobox pattern:** focus stays in the field, which has `role="combobox"`, `aria-autocomplete="list"`, `aria-expanded`, and while open `aria-controls` (the `listbox`) and `aria-activedescendant` (the highlighted `option`, `aria-selected`). The note is in the option's text for screen readers.
- **Keyboard, while open:** Up/Down move the highlight (wrapping), Enter accepts it, Escape closes it, Tab closes it without accepting and moves on as usual. Modified keys pass through, so ⌘Enter still inserts a row. The table hands every key to the popup first, so Up/Down do not change row while it is open; when it is closed, Up/Down/Enter behave as before. None of these keys is a global shortcut, so the window listener never takes them.
- **Mouse:** hovering highlights, a click accepts; the popup prevents `mousedown`, so the field keeps focus.
- **Placement:** a portal on `document.body` (like `ContextMenu`), `position: fixed` under the anchor (the table cell) and at least as wide, flipped above when it does not fit below, kept inside the window horizontally. It closes when the field loses focus, on window resize and on scrolling outside it.
- **Accepting** sets the field's text to `value` through the table's `onChange` (so auto-save gets it like typing) and puts the caret at the end.

### Persistence

UI settings (the `settings` store) are saved in the Go settings file, `settings.json` ([settings.md](settings.md)), through `commands/settings.ts`:

- At startup `useSettingsPersistence` (called by `App`) runs `loadSettings(stores)`, which dispatches `settings/load` with the saved values. The reducer drops invalid ones.
- `trackSettings` saves `theme`, `customTheme` and `sidebarCollapsed` whenever they change in the store. `commitSplitRatio(stores, ratio, position?)` updates the store and queues a save of the split of the layout in effect (`splitRatio` or `splitRatioBelow`). Saves are debounced by 400ms; nothing is saved per drag frame. Queued saves are flushed when the page is hidden or unloaded, and when the shell unmounts.
- `followSettingsChanges` applies hand edits of the file live: Go emits `settings:changed` and the new values go through `settings/load`. Settings applied this way are not saved back.
- The settings screen saves with `applySetting(stores, patch)` instead: at once, and into the store only after Go accepted it, so a refused value changes nothing and its error is shown under the field.
- The backend is a `SettingsPersistence` (`lib/persist.ts`: `load()`, `save(patch)` and an optional `subscribe(onChange)`). `main.tsx` calls `installGoSettings()`, which installs `goSettingsPersistence()` (`lib/settings.ts`, over `SettingsService`) wrapped in `withLocalStorageMigration`, so settings saved under `postsonde.ui` by earlier builds move into the file once. Tests keep the default `localStorageSettings()` or install a fake with `setSettingsPersistence`.
- The theme is also cached in `localStorage` (`postsonde.theme`) by `applyTheme`, only as the first-paint hint for `public/theme-init.js`, which `index.html` loads.

## Themes

Light, dark and system themes (UI-04). The preference is `settings.theme` (`system`, `light`, `dark`), saved in `settings.json` as `ui.theme` ([settings.md](settings.md)); `system` is the default.

- **Where it is set:** the title bar's theme button cycles System → Light → Dark (its icon is the preference: monitor, sun, moon; its label also names the applied theme, e.g. "Theme: System (Dark)"). It dispatches `settings/setTheme`, which `trackSettings` saves. The settings screen's General page has the same choice as a System / Dark / Light switch, saved through `applySetting`. A hand edit of the file applies live through `settings:changed`.
- **Tokens:** `styles/tokens.css` holds both token sets, picked by `data-theme="dark|light"` on `<html>` (dark is also the fallback with no attribute). Every colour elsewhere is a `var(--…)`; `scripts/check-css-tokens.sh` fails on literal colours outside `tokens.css`. Each theme sets `color-scheme`, so scrollbars and native form controls follow. Both meet WCAG AA contrast, checked by `styles/contrast.test.ts` (see [Accessibility](#accessibility)).
- **Applying:** `styles/theme.ts`. `applyTheme(pref)` resolves the preference, sets `data-theme`, caches the preference in `localStorage` (`postsonde.theme`) and notifies `subscribeTheme` listeners when the applied theme changes. `currentTheme()` reads the applied theme; the `useAppliedTheme()` hook (`styles/useAppliedTheme.ts`) re-renders with it.
- **First paint:** `index.html` loads `public/theme-init.js` as a blocking classic script (the CSP forbids inline scripts). It resolves the cached preference against `prefers-color-scheme` and sets `data-theme` before anything paints; `main.tsx` then calls `applyTheme(storedThemePreference())`, and the settings file has the final say once loaded. The cache can only be stale after a hand edit made while the app was closed: then the first frames show the old theme. Before the page paints at all, the native window shows its background colour, which Go sets from the saved theme's `--bg0` (`internal/app/theme.go`); with `system` it starts dark and is corrected to the OS theme when the app has started.
- **Following the OS:** for `system` the OS theme is the web view's `prefers-color-scheme`, watched for changes for the app's whole life. Go also listens to the Wails `common:ThemeChanged` application event and emits `system:themeChanged` `{dark}` (`internal/app/services/system/events.go`); `lib/osTheme.ts` (started by `main.tsx`) passes it to `setSystemDark`. The latest of the two signals wins. On Linux, `lib/osTheme.ts` also asks Go once at startup (`System.IsDarkMode()`, the freedesktop portal's `color-scheme`) and takes the answer when it is dark; a light answer cannot be told from "no preference", so it is left to the media query.
- **CodeMirror:** the editor theme (`components/editor/theme.ts`) uses tokens only, so switching `data-theme` restyles open editors. `CodeEditor` also keeps CodeMirror's `EditorView.darkTheme` facet in step through an `appearance` compartment (`appearanceExtension` in `extensions.ts`), reconfigured on every `subscribeTheme` change without re-creating the view; a new document (`docKey`) starts in the current mode. That picks CodeMirror's own `&light`/`&dark` base styles (all overridden by token rules of the same specificity) and is what extensions read. `CodeEditor` creates every `EditorView` in the app, so every editor, single-line fields included, follows.
- **Custom themes (UI-05):** a theme file in `<data>/themes/` (`settings.customTheme`, `ui.customTheme`) sets token colours on `<html>` with `style.setProperty` and pins `data-theme` to its base through `setThemeOverride`; the preference is kept for when it is removed, and the title bar's theme button removes it. `styles/customTheme.ts` applies it, `useCustomThemeSync` (called by `App`) picks it from the files Go listed, `public/theme-init.js` applies the cached one before first paint. Format, checks and settings UI: [themes.md](themes.md).
- **Native window frame:** the title bar of the window itself (macOS), the caption (Windows) and the GTK header bar (Linux) follow the OS theme, not the app's preference. With a forced Light or Dark on an OS in the other mode, the frame keeps the OS look.

## Editor settings

The editor settings (UI-08: font family and size, tab size, word wrap, line numbers, bracket matching) are in the `settings` store (`editor…` keys, section `editor` of `settings.json`, [settings.md](settings.md)) and set on the settings screen's Editor page, which has a live preview. Every CodeMirror editor follows them live, without re-creating its view:

- `useEditorPreferencesSync` (called by `App`) hands them to `setEditorPreferences` (`components/editor/preferences.ts`) whenever they change, whoever changed them.
- **Font:** written as CSS variables on `<html>`: `--font-editor` (the font, quoted, then the `--font-mono` stack for a font that is not installed; `monospace` and `ui-monospace` stay unquoted), `--fs-editor` and `--lh-editor` (22px at 12px, in proportion). `tokens.css` has the defaults and the default values remove the variables. The code editor theme uses all three; one-line fields (the URL) take only the family, their size stays `--fs-mono-lg`.
- **The rest** is `preferencesExtension(prefs)`: `EditorState.tabSize` and `indentUnit` (spaces), `EditorView.lineWrapping`, `lineNumbers()` and `bracketMatching()`, one cached instance per preferences object. `buildExtensions` puts it in a `preferences` compartment (before `baseExtensions`, so the line numbers are left of the fold gutter; one-line fields get an empty extension). `CodeEditor` reconfigures that compartment on every `subscribeEditorPreferences` change, and after a `docKey` change for a kept state made with other settings, then asks CodeMirror to measure again for the new font metrics.
- Only CodeMirror views follow the settings. Monospace text outside CodeMirror (tables, message log rows, metadata) keeps `--font-mono` and `--fs-mono`.

## Dialogs and toasts

### Dialog

`components/common/Dialog` is the one modal dialog: `<Dialog open title onCancel onConfirm confirmLabel cancelLabel hideCancel confirmIcon variant confirmDisabled busy width initialFocus describedBy bodyClassName>{body}</Dialog>`. Nothing renders while `open` is false. `hideCancel` leaves the Cancel button out of the footer (a last step with only Done); Esc and the close button still cancel.

- **Look:** a panel (default 440px, `width` for others, never wider than the window) on `--bg1` with a `--line2` border, `--radius-xl` and `--shadow`, over `--scrim`, top-aligned 64px from the top of the window. Header: the 14px semibold title and a 24px close button. Body: a column with 14px gaps (`bodyClassName` replaces its padding and gap). Footer, only when `onConfirm` is given: on `--bg0` under a `--line` border, Cancel (secondary) then the confirm button, right-aligned. `variant="danger"` draws the confirm button with a `--bad` border and text on a transparent fill; pass `confirmIcon={<IconTrash size={14} />}` for deletes. `busy` shows a spinner in the confirm button.
- **Portal and ARIA:** rendered in a portal on `document.body`; `role="dialog"`, `aria-modal="true"`, `aria-labelledby` the title, `aria-describedby={describedBy}`. While open every other child of `body` gets the `inert` attribute (removed again on close, only where the dialog set it), so screen readers, Tab and the pointer stay in the dialog; `body` does not scroll.
- **Focus:** on open, focus goes to `initialFocus`; else, in a danger dialog, to **Cancel** (Enter then does not delete by accident); else to the element marked `data-autofocus` or the first form field; else to the confirm button when enabled; else to the first focusable element (the close button). Tab and Shift+Tab wrap inside the panel, and focus that still lands outside (engines without `inert`) is pulled back. On close, focus returns to the element that had it.
- **Keys:** Escape cancels. Enter confirms unless focus is in a text area, a contenteditable (CodeMirror) or an `aria-multiline` field, or on a button, link, select or option (they handle Enter themselves), unless it has a modifier or is a key repeat, during IME composition (`isComposing`, keyCode 229), and while the confirm button is disabled or `busy`. A child that handles Escape or Enter itself calls `preventDefault()`, and the dialog leaves the key alone (an open autocomplete closes first). The panel is `data-shortcut-scope="dialog"`, so only `inDialog` global shortcuts run inside (see Keyboard shortcuts).
- **Cancelling:** Escape, the close button, Cancel and a click on the scrim call `onCancel` for a default dialog. For a danger dialog the scrim does nothing, so a stray click never answers a delete. While `busy`, confirm and every cancel are blocked (the async work is not cancellable from the dialog); buttons use `aria-disabled` instead of `disabled`, so focus stays on them.
- **Nesting** is not a designed pattern, but works: a dialog opened from a dialog makes the outer one inert and gives it back, with focus, when it closes.

### confirm()

`confirm({ title, message, confirmLabel, cancelLabel, variant, confirmIcon })` (`commands/dialogs.ts`) returns `Promise<boolean>`: true when the user confirms, false when they cancel. `ConfirmHost` (in `Dialog.tsx`, mounted once by `AppShell`) shows the requests one at a time, oldest first, with `message` as the dialog's description. The pending requests hold resolve functions, so they live in a small queue in `commands/` (`createConfirmQueue`, like `shortcutBindings`), not in a store. Without a mounted host `confirm()` logs an error and resolves false; when the host unmounts, pending requests resolve false. Components ask, then call the command:

```tsx
if (await confirm({ title: `Delete environment “${name}”?`, message, confirmLabel: "Delete environment", variant: "danger" })) {
  await deleteEnvironment(stores, id);
}
```

Used by the environments panel's Delete ([environments.md](environments.md)). Tests render `<ConfirmHost queue={createConfirmQueue()} />`, or the default host next to the component under test.

### Toasts

`showToast({ message, icon, action: { label, run }, shortcut, duration })` (`commands/toasts.ts`) returns the toast's id; `dismissToast(id)` removes it. `ToastHost` (`components/common/Toast.tsx`), mounted by `AppShell` inside the main column, shows them.

- **Look:** centred at the bottom of the work area, 16px above the 26px status bar; a 40px row on `--bg1` with a `--line2` border, `--radius-lg` and `--shadow`: the optional icon (`--text3`), the message, the action button (accent, semibold), the shortcut hint in the shortcut help's key style, and a dismiss button; under it a 2px `--accent` bar on `--line` that shrinks over the remaining time.
- **Timing:** dismissed after `duration` ms, 8000 by default (`DEFAULT_TOAST_DURATION_MS`); `0` or `Infinity` stays until dismissed (no bar). The pointer over the toasts, or focus inside them, pauses every countdown; the bar pauses with it.
- **Stack:** at most 3 (`MAX_TOASTS`), newest at the bottom; a fourth drops the oldest.
- **Action:** choosing it dismisses the toast, then runs `run` (a rejected promise is logged). `shortcut` is display only: the feature that shows the toast binds the key (⌘Z for Undo), since the toast cannot know when ⌘Z should undo instead of editing text.
- **Screen readers:** the list is an `aria-live="polite"` region that is always in the page, so each new toast is announced without moving focus. There is no assertive variant: an error that needs attention belongs next to what failed (inline `role="alert"` or the status bar), not in a toast that goes away. The shortcut hint is `aria-hidden`; the action button is described by the message. While toasts show, the host is a `region` named "Notifications".
- **Keyboard:** the toasts are in the Tab order after the status bar, and F6 (`notifications.focus`) focuses the newest toast's action (or its dismiss button); with no toast F6 goes through. When a focused toast goes away, focus moves to the next toast, or back to where it was before it entered the toasts.
- **Motion:** toasts slide in over 160ms. With `prefers-reduced-motion: reduce` they appear without it and the countdown bar is hidden (the global rule in `base.css` shortens every animation, which would empty the bar at once); the timer still runs.
- Toasts are app-wide, not per project: `ToastHost` clears them when it unmounts (the project closes). Like `confirm()`, they carry callbacks, so they live in `commands/` (`createToaster`), not in a store; tests pass their own `toaster` to `ToastHost`.

The environments panel shows "Deleted environment “…”" after a delete. The undo toast comes with tree deletes.

## Collection tree

`components/tree/CollectionTree` is the Collections sidebar view (COL-01, COL-02): the open project's folders and items.

- **Data.** `App`'s project shell calls `useCollectionSync`, which runs `followCollection` (`commands/collection.ts`): it loads `CollectionService.Tree()` into the store with `collection/load` (nodes mapped by `toTreeNode`), again when another project opens and on the Go event `collection:changed` (`lib/collection.ts`, sent by tree operations; `applyCollectionChanged` also gives an open draft a renamed request's new name, see [collection.md](collection.md#tree-operations-and-pending-edits)), and clears the store when the project closes. A tree that arrives after another project opened is dropped.
- **Rows.** Folders: chevron, folder icon (accent at the top level), name, a green badge with the kind and bound port while the folder's saved server listens (`WS :8081`, `MOCK :8080`; `selectFolderServerBadge`, SRV-04, also read out in the row's `aria-label`), item count. The count is **recursive**: every non-folder item in the folder's whole subtree (requests, unknown and invalid items), not subfolders (`countItems`). Items: a 38px mono badge, then the name. A folder or item that is read-only has the reason as tooltip; an invalid file is shown in italics with a warning icon, and its load problem (from `problems`) is the tooltip and `aria-description`.
- **Badges** (`components/tree/badges.ts`): HTTP methods `GET` `POST` `PUT` `PATCH` in their `--m-*` colour, `DELETE` as `DEL` (`--m-del`), other methods in `--m-dir`; GraphQL `GQL` (`--m-gql`); by file kind for other protocols: `WS`, `SIO`, `SSE` in `--m-ws`, `GRPC`, `TCP` and any other kind (at most 5 letters) in the neutral `--m-dir`; an invalid file's badge is `--warn`. No tokens were added for gRPC, Socket.IO, SSE or TCP. A `websocket` request shows `WS`, a `grpc` request `GRPC`.
- **Expanded folders** are remembered per workspace in its local UI state under the key `tree.expanded` (`lib/treeExpansion.ts`, at most 5,000 ids; see Workspace switching). They are local data that must stay out of the project (file-format.md) and the settings file is global. Builds before STO-06 kept them in `localStorage` under `postsonde.tree.expanded.<workspaceId>`; that is still read while the local UI state has none. It sits behind `ExpansionPersistence`, a `WorkspaceLocalStore` (`lib/workspaceLocal.ts`, shared with the open tabs). The first time a project's tree is shown, the remembered folders are expanded, or the top-level folders when nothing was saved. A reload of the same project keeps the current expansion. Changes are saved 300ms after the last one, and when the page is hidden, before the project is left and when it closes.
- **Opening.** Clicking a folder or pressing Space on it toggles and selects it; the chevron only toggles. Enter or a double-click on a folder opens its `DIR` tab (`openTreeItem` → `openFolder`) as a kept tab, without changing its expansion (a double-click's two clicks toggle it twice); folders never open in the preview tab. A single click on a request, or Space on it, selects it and opens it in the [preview tab](#tabs) (`openTreeItem(stores, id, { preview: true })`); a double-click or Enter opens it as a kept tab (and keeps it if it was the preview). Moving with the arrow keys opens nothing. Unknown and invalid items are only selected.
- **Keyboard** (WAI-ARIA tree): `role="tree"` with flat `treeitem` rows carrying `aria-level`, `aria-setsize`, `aria-posinset`, `aria-expanded` (folders) and `aria-selected`. One row is in the Tab order (roving tabindex): the focused row, else the selection, else the first row. Up/Down move, PageUp/PageDown move a page, Home/End go to the first and last row, Right expands a folder or moves to its first child, Left collapses or moves to the parent, and typing letters moves to the next row whose name starts with them. When a collapse hides the focused row, its folder takes over.
- **Virtualization.** No library. `flattenVisibleRows` lists the visible rows (children of expanded folders only). Every row is 30px, absolutely positioned at `index × 30px` inside a sizer as tall as all rows, and only the rows in the scroll window plus 10 above and below are rendered, plus the focused row wherever it is, so keyboard focus survives scrolling. The windowing is the shared `components/common/useVirtualRows` hook (see [Windowing](#windowing)). Moving focus with the keyboard scrolls its row into view first. A test renders 5,050 rows and checks the DOM stays at the window size (about 40 rows).

- **Context menu.** A right-click on a row or on the tree's empty area, or Shift+F10 / the Menu key on the focused row (`tree.menu`, scope `tree`; the tree is marked `data-shortcut-scope="tree"`), opens the shared `ContextMenu` with New request and New folder (below), and on a row Rename…, Duplicate, Move to folder…, Move up, Move down and Delete ([Rename, duplicate and delete](#rename-duplicate-and-delete), [Move and reorder](#move-and-reorder)), then the sort choices ([Sorting](#sorting)). Only when the tree gets `onNewItem` or `actions`, which the Collections sidebar passes; disabled in a read-only project.
- **Focus.** A row that gets focus any other way (a dialog or menu giving it back) becomes the focused row, so the keys act on it.

Not yet: a folder settings button (a folder's settings open in its `DIR` tab, Enter or a double-click, see [Folder settings](#folder-settings)), and a trash view (`ListTrash`, `PurgeTrash`).

### Sorting

COL-05. Each folder, and the top level, is shown in its **manual order** (the `order` in the project, [collection.md](collection.md#order); the default) or **sorted by name**.

- **A view preference.** Sorting changes only how the tree shows a folder: nothing is written to the project, the manual order stays as it is underneath and comes back unchanged when the folder returns to manual order. So a teammate's tree is not reordered by someone's view, and a folder can be browsed sorted without losing a hand-made order. The choice is saved at once per folder (by id) in the workspace's local UI state under `tree.sort` (`lib/treeSort.ts`, a `WorkspaceLocalStore`; [workspace.md](workspace.md#view-state)) and read when the project's tree is first shown. It lives in the store as `collection.sortedByName` (folder ids, `TOP_LEVEL` = `""` for the top level); `setFolderSort(stores, parentId, mode)` (`commands/collection.ts`) changes and saves it.
- **Order.** `sortIdsByName`: folders first, then the other items, by name with `Intl.Collator` (ignoring case and accents, numbers in numeric order: "Step 2" before "Step 10"), ties by id. `flattenVisibleRows(…, { sortedByName })` sorts the items of the expanded sorted folders only. Only this folder's own items are sorted; its subfolders keep their own choice.
- **Choosing.** The context menu ends with two choices (`menuitemradio`, the current one checked): on a folder "Keep “Orders” in manual order" and "Sort “Orders” by name"; on any other item the same for the folder it is in, and on a top-level item or the empty area for the top level ("Sort the top level by name"). Works in a read-only project too (nothing is written).
- **Reordering a sorted folder.** Its items have no manual places to go to, so: Move up and Move down are disabled with a tooltip saying why, and Alt+↑/↓ shows that hint as a toast ("“Orders” is sorted by name. Choose “Keep “Orders” in manual order” in the menu to reorder by hand.") instead of moving. A drag over a sorted folder's items or onto the folder drops **into** it: the folder row is highlighted (for the top level, the whole tree gets an accent ring) and no line is drawn; the item goes last in the folder's manual order and shows in its sorted place. Dragging an item within its own sorted folder is refused. `move.ts` does this (`isSortedByName`, `stepTarget`, `dropTarget`, `dropAtEnd`), so the rules are tested without the DOM.

### Sidebar filter

NAV-06. The field above the tree ("Filter by name or method") filters it as you type. ⇧⌘E (`collection.filter`, Ctrl+Shift+E elsewhere; ⇧⌘F is Beautify JSON body) shows the Collections view, closing the settings screen and opening the sidebar if needed, and focuses and selects the field. It is disabled until a tree is loaded, and cleared when another project opens.

- **Matching** (`components/tree/filter.ts`, pure): `buildFilterIndex` lists every node with its lower-case name and method words (method, badge label, file kind) once per tree; `filterTree` is one pass over it per query, so a tree of thousands of requests filters in a few milliseconds (`filter.test.ts` checks 5,000 requests stay under a 16 ms median). Names match with the quick switcher's `fuzzyMatch` (`lib/fuzzy.ts`), held tighter: the letters in order, where each run after the first starts a word ("lprod" finds List products, "user" finds List users, but "usr" does not match everything that has those letters somewhere). A query that starts with a method or kind word (`get`, `post`, `put`, `patch`, `delete`/`del`, `head`, `options`, `gql`/`graphql`, `grpc`, `ws`/`websocket`, `sio`, `sse`, `tcp`, `http`, …) also matches the items of that method or kind whose name matches the rest: "post user" finds the POST requests with "user" in the name, "del" every DELETE request. A query that is only such a word matches other names only where the word appears as is ("get" finds Get order, "put" does not find Update settings).
- **What shows.** The matching items and folders, every folder above one of them, and everything inside a folder that matches by name (collapsed until opened). The matched letters are highlighted (`<mark>`, accent and semibold, the shared `components/common/Highlighted`), and a badge matched by method is underlined. Sorting still applies.
- **Expansion.** While filtering, the folders above the matches are open, and opening or closing a folder changes only the filtered view (kept per query), never the store: clearing the filter brings back the expansion as it was. A new query opens the folders above its matches again.
- **Keyboard.** ↓ or Enter in the field focuses the tree on its Tab-stop row: the focused row if still shown, else the selection, else the first match. Arrow keys, type-ahead, Enter and the context menu work on the shown rows. Esc in the field clears it; the × button clears it too and keeps focus in the field.
- **Moves while filtering.** Drag and drop and Alt+↑/↓ are off (a toast says to clear the filter), since the rows between which an item would land are not all shown. Move to folder…, rename, duplicate and delete work as usual.
- **Empty state.** "No matches" with "No folder or request matches “…” by name or method." and a Clear the filter button. A polite `status` says how many nodes match; the tree's name becomes "Collections, filtered".
- **Speed.** The Sidebar passes the filter to the tree through `useDeferredValue`, so typing stays smooth; the index is rebuilt only when the tree changes.

### Move and reorder

COL-04 (move). Items move into another folder or to another place in their folder, by mouse (native HTML5 drag and drop) or by keyboard. Every move goes through `moveNode` (`commands/collection.ts`): it sends the queued edits of every request in the item first (`flushRequests`), calls `moveItem` (Go's `Move`, which writes the new `order` of the folders it changes, [collection.md](collection.md#tree-operations)), applies the returned tree, and reveals and selects the item. IDs do not change, so open tabs and drafts of moved requests keep working. A failure is a toast ("Could not move “Health”. …"), and the tree is read again. `useTreeActions` provides `move` and `moveTo` (the dialog) to the tree.

- **What can move where** (`components/tree/move.ts`, pure, mirroring Go's checks so the UI refuses what Go would): nothing in a read-only project or out of a folder whose `_folder.json` is read-only; nothing into a read-only folder; a folder never into itself or one of its folders; a symbolic link only within its folder. Unknown, invalid and newer-version items can move (Go moves the file unchanged). A move that changes nothing is not sent.
- **Drag and drop** (`useTreeDrag.ts`): movable rows are `draggable`; the drag carries the item's id as `application/x-postsonde-tree-node` with `effectAllowed = "move"`. Over a folder row, the top quarter drops before it, the bottom quarter after it, and the middle **into** it (the row is highlighted with `--accent-dim` and an accent ring); over any other row, the top half drops before and the bottom half after. Between items an accent **line** with a small circle shows where it lands, indented to the level it would get. After an open folder that has items means before its first item. Below the last row is the end of the top level. Resting on the middle of a collapsed folder for 600 ms expands it. A refused drop (into its own subfolder, a read-only target, a no-op) shows no indicator, and `dropEffect` is `none`, so the pointer shows it cannot drop. The dragged row is dimmed.
- **Only the tree's own drags.** The tree reacts only to a drag that started on one of its rows (it remembers the id at `dragstart`). Anything else, such as files dragged in from the OS or text, gets no `preventDefault()` in `dragover`, so the tree is never a drop target for it. The app does not enable Wails' file drop (`EnableFileDrop`), so the webview does not intercept the tree's drags either.
- **Keyboard** (scope `tree`, `lib/shortcuts/registry.ts`): Alt+↑ / Alt+↓ (`tree.moveUp`, `tree.moveDown`) move the focused item one place up or down in its folder, and focus stays on it; at the edge of its folder nothing happens. ⇧⌘M (`tree.moveTo`, Ctrl+Shift+M elsewhere) opens **Move to folder**. The keys are taken even when the item cannot move, so Alt+↑/↓ never move focus instead. The context menu has the same three items, disabled when they would do nothing.
- **Sorted folders and the filter.** In a folder sorted by name items cannot be reordered, only moved in ([Sorting](#sorting)); while the tree is filtered, drag and drop and Alt+↑/↓ are off ([Sidebar filter](#sidebar-filter)).
- **Move to folder dialog** (`MoveDialog` in `TreeActionDialogs.tsx`): the New item dialogs' folder picker (`FolderSelect.tsx`, shared), starting on the item's own folder; the item itself, its folders, read-only folders and, for a symbolic link, every other folder are disabled. Below it, where the file or directory moves (`orders/get-order.json → empty/get-order.json`; Go keeps the name, adding a `-2` suffix only when it is taken). Move is disabled until another folder is chosen; the item goes last there. A failure shows in the dialog.

### Rename, duplicate and delete

COL-04 in the tree. `useTreeActions` (`components/tree/useTreeActions.tsx`, used by `Sidebar`, which passes it to the tree as `actions`) holds the dialogs and the last delete; the commands are in `commands/collection.ts`. Only writable folders and requests can be renamed, duplicated or deleted (`canEditNode`): not in a read-only project, not read-only, unknown or invalid items (their menu items are disabled and the keys do nothing).

- **Inline rename** (the default): F2 (`tree.rename`) turns the focused row's name into a field (`InlineRename.tsx`) with the whole name selected. Enter renames, Esc cancels, and leaving the field renames when the name is valid and changed, else cancels. Names are checked as for new items, not counting the item itself (`validateRename` in `newItem.ts`: required, at most 200 characters, no control characters, no sibling with the same name ignoring case); the reason, or Go's error, shows in a small box under the field and the edit stays open. Keys and clicks in the field do not reach the tree. The row stays rendered (pinned) while it is edited; if the item goes away, the edit ends. Afterwards focus is back on the row.
- **Rename dialog** (the context menu's Rename…, the fallback): the name with the current one selected, and a box saying where the file or directory moves (`renamePreview`, a port of Go's `renamedEntry`: `orders/cancel-order.json → orders/cancel-an-order.json`, or that it keeps its name). A failure shows under the name.
- **Renaming** (`renameNode`): for a request, `flushRequests` first (an edit in flight must not write the old name back, [collection.md](collection.md#tree-operations-and-pending-edits)), then `renameItem`, the returned tree, and `applyRenamed` for an open draft. Tab titles follow on their own: the tab bar reads names from the collection store.
- **Duplicate** (menu, or ⌘D, `tree.duplicate`; `duplicateNode`): flushes the requests' queued edits, `duplicateItem`, then the copy (Go puts it right after the original, named "… copy") is revealed and selected, not opened. A failure is a toast.
- **Delete** (menu, or Delete / Backspace, `tree.delete`): a folder with contents asks first (`DeleteFolderDialog`, danger variant: Cancel focused, the scrim does not cancel): "Delete folder “Orders”?", what moves to the trash ("the 2 folders and 5 requests"), the requests with their badges (at most 8, then "and N more"), and Delete folder. Single requests and empty folders are deleted at once. `deleteNode` flushes the requests' queued edits (so the trash has them), notes the open tabs of the item and everything in it (id, index, pinned) and the active tab, calls `deleteItem`, closes those tabs and applies the tree. Focus moves to the row that took the deleted one's place. A failure is a toast and closes nothing.
- **Undo toast**: "Deleted “Name”" with the trash icon, Undo, the ⌘Z hint and the standard 8 s countdown (paused on hover or focus). Undo runs `restoreNode`: `restoreItem`, the tree, then the tabs that closed with it open again at their old indexes, pinned again, and the tab that was active at the delete is active again (else the current one stays); the restored item is revealed and selected. Tabs of items whose id changed on restore (another item took it meanwhile) stay closed. A delete in one project is never restored into another. ⌘Z (`collection.undoDelete`, global) runs the newest delete's Undo while its toast shows; it goes through in text fields and editors (their own undo) and when no Undo toast shows. After the toast is gone the item stays in the project's trash (`ListTrash`, restorable later through `Restore`).

### New folder and new request

The New folder and New request dialogs (COL-04, creating items) are the shared [Dialog](#dialog) with a form, in `components/tree/NewItemDialog.tsx`; the pure parts are `components/tree/newItem.ts`.

- **Opening.** The Collections header's New folder and New request buttons, the tree's context menu, and ⌘N (`request.new`) in any sidebar view. `useNewItemDialog` (used by `Sidebar`) holds which dialog is open; the buttons are disabled until a tree is loaded and in a read-only project (the tooltip says why).
- **Type** (New request only): a segmented radio group of every kind `CreateRequest` accepts, in this order: HTTP (the default), GraphQL, WebSocket, TCP, gRPC, SSE, Socket.IO, with a one-line description of the chosen one.
- **Name.** Focused when the dialog opens. Required (Create is disabled while it is blank); refused, with the reason under the field (`aria-invalid`, `role="alert"`), when it is longer than 200 characters, contains line breaks or other control characters, or equals the name of an item already in the target folder (ignoring case and surrounding spaces). The name is trimmed before it is sent.
- **Folder.** Defaults to the folder the dialog was asked for: the context menu's row, else the tree's selection; for an item that is its folder, and the top level when there is none or it is read-only. A native `<select>` (invisible, over a field drawn with a folder icon, the name, "top level" for the project's top level, and a chevron) lists the top level (the project name) and every folder, collapsed ones too, indented by depth; read-only folders are disabled. Under it, the file path the item will get (`previewPath`): a port of Go's `Slug`, with the `-2`, `-3` suffix for names taken in the folder. Files outside the tree (fixtures, scripts) are not known to the UI, so Go may still pick another suffix.
- **Creating.** Create (or Enter in the name field) calls `createItem` (`commands/collection.ts`): `CollectionService.CreateFolder` or `CreateRequest` at the end of the folder, then the returned tree goes into the store, the folders above the new item are expanded, and it opens in a **kept** tab: a request in its editor, a folder as its `DIR` tab, which also selects it so the next New folder nests inside it. ### Scratch requests

Scratch requests (COL-06) are quick requests kept in the workspace's local side files, not in the project, until "Save to…" moves one into a folder ([collection.md](collection.md#scratch-requests)). They are found in three places, and deliberately **not** in the Collections tree: their tabs (restored across restarts like any tab), the tab bar's `+`, and the request pane when no tab is open.

- **Store.** Every tree from Go carries `scratch` nodes. `applyTree` puts them into `collection.nodes` (requests with `parentId: null` and an empty `path`) and their ids into `collection.scratchIds` (sorted by name), not into `rootIds`, so the tree, its counts and the quick switcher ignore them while tabs, editors, undo/redo, drafts, auto-save and sending find them by id like any request. `selectIsScratch(state, id)` tells them apart.
- **Creating.** The tab bar's `+` and the chevron next to "New scratch request" in the empty state open a `ContextMenu` of every request kind (HTTP, GraphQL, WebSocket, TCP, gRPC, SSE, Socket.IO); the empty state's button makes an HTTP one. `createScratchRequest(stores, kind, name, open)` (`commands/collection.ts`) calls `CreateScratch` (Go names it "Scratch N" when `name` is blank), applies the tree and opens it in a kept tab (with `open` false the caller opens it: the history panel fills it first, [history.md](history.md#restore)).
- **Tabs.** A scratch tab shows a small "scratch" tag after its name (its accessible name ends in ", scratch request"; the tooltip says it is not in the project). Its context menu adds Save to… and Delete scratch request.
- **Empty state** (`components/tabs/NoTabState.tsx`, the request pane with no tab open): "No request open", New scratch request, and a "Scratch requests" list with Open, Save to… and Delete for each.
- **Save to…** is the New request dialog (`NewItemDialog` with `type: "saveScratch"`): no type picker, the name filled in with the scratch request's, the same folder picker, path preview and name checks, and a Save request button. `saveScratchTo(stores, id, parentId, name)` sends the queued edits (`flushRequests`), calls `SaveScratch`, applies the tree, gives an open draft the new name (`applyRenamed`) and reveals and selects the request. It keeps its id, so its tab, draft and edit history stay as they are. Disabled while no tree is loaded and in a read-only project.
- **Delete** asks first (`confirm`, danger: it cannot be restored), then `deleteScratchRequest` sends the queued edits, closes the tab without remembering it and calls `DeleteScratch`.

`useScratchActions` (`components/tabs/useScratchActions.tsx`) holds the kind menu, the Save to… dialog and the delete confirmation for the tab bar and the empty state.

### Dropped files

Files dragged from the OS onto the window are imported (IMP-11, [import.md](import.md#dropped-files)). Wails delivers the drop natively with real paths; JS never reads the files.

- **Target.** `AppShell`'s root carries `data-file-drop-target="import"` (`IMPORT_DROP_TARGET`, `commands/fileDrop.ts`). Go sends `collection:files-dropped` with the paths and the target's attribute value (`onFilesDropped`, `lib/collection.ts`). A drop target inside the shell (none yet; a multipart file field would be one) takes precedence by declaring its own value: the runtime picks the innermost target, and the import ignores drops for other targets. Modal dialogs are portals outside the shell, so dropping on an open dialog does nothing. The welcome screen has no target.
- **Overlay.** `useFileDrop` and `FileDropOverlay` (`components/shell/FileDrop.tsx`): Wails' runtime puts `file-drop-target-active` on the target under a file drag (from native drag callbacks on macOS and Linux, from DOM drag events on Windows, only for drags carrying files), and a `MutationObserver` on the shell turns that into "Drop to import" over the whole window (`pointer-events: none`, so the runtime's `elementFromPoint` still sees what is under it). Text drags and the tree's own drags never set it. Over a read-only project it says so instead. As a safety net for a drag that leaves the window without the runtime noticing, the first pointer move, pointer down or Escape afterwards hides it.
- **Drop.** `importDroppedFiles` (`commands/fileDrop.ts`) needs a loaded, writable project (a toast says why not), asks `detectImport` for all paths, lists the files that cannot be imported in one toast (`refusedMessage`), and hands the rest to `useNewItemDialog` (`onImportDroppedFiles`), which queues one Import dialog per file, keyed so each is fresh, titled "Import (1 of 2)", previewed in its detected format ("(detected)"); closing one opens the next. More than 20 files is Go's `import.too_many_files`, shown in a toast.

### External changes

Go polls the open project's files and sends `collection:external-change`
when files were changed outside PostSonde (STO-05,
[collection.md](collection.md#external-changes)). `followExternalChanges`
(`commands/externalChanges.ts`, mounted by `useCollectionSync`) applies it
with `applyExternalChange`, and calls `setWatching(false)` while the
window is hidden (`visibilitychange`), `true` when it is shown again:

- **The tree** is loaded again (`loadCollection`); names, badges, order and
  new or removed items follow, and the saved servers sync as on any reload.
- **A clean draft** (open tab, no unsaved edits) of a `modified` request or
  folder is loaded again from Go (`loadRequestDraft`, `loadFolderDraft`),
  which clears its undo history (`clearEditHistory`): the old content's
  steps no longer apply. An `added` ID with a draft is a file that came
  back (a checkout) and is handled the same way.
- **A dirty draft** of a `modified` item, or one Go lists in `conflicts`, is
  in **conflict** (`drafts/conflict`, `drafts.conflicts`). Go set its
  pending edit aside and refuses edits of it until resolved; the UI holds
  them too: `commands/autosave.ts` queues edits of a draft in conflict but
  does not send them (no "Saving…"), and `dropQueuedEdits` forgets the
  saves Go will not report (`autosave/abandon`). `ExternalChangeBanner`
  (above the editor in `TabPanel`) says so and offers **Keep mine**
  (`keepMine`: `ResolveConflict`, then `sendDraft` sends the draft, which
  is written over the file), **Take theirs** (`takeTheirs`: `ResolveConflict`,
  the draft is replaced by the file's version with `drafts/replace`, clean,
  and its undo history cleared) and **Show changes** (a dialog with a line
  diff, `lib/lineDiff.ts`, of the draft and the file's version as indented
  JSON, `loadConflictVersions`). An edit Go refuses with
  `collection.changed_on_disk` is not reported as a failed save.
- **A removed request with an open tab** keeps the tab and its content: its
  node stays in the collection store (`deletedIds`, readOnly `deleted`,
  `parentId` the folder it was in) outside the tree, so `followTabs` does
  not close it and the editors are read-only ("This request's file was
  deleted outside PostSonde…"). The tab shows a `deleted` tag. The banner
  offers **Restore file** (`restoreDeletedRequest`: `RecreateRequest` with
  the tab's content into its folder, or the top level; the draft becomes
  clean) and **Close**. Closing the tab forgets the node
  (`collection/forgetDeleted`); a file that comes back makes it an item
  again. Tabs of removed folders close, as after any reload.
- **Environments**: `environments` reloads the environment list
  (`loadEnvironments`); Go also sends `environments:changed`, so the
  `{{variable}}` chips reload. **Global variables**: `globals` tells the
  views that loaded them (`onExternalGlobalsChange`): the Global variables
  panel loads them again.

- **Another window's edit** (APP-06, `collection:edited`) is applied by
  `applyEditedElsewhere`: once this window's queued edits of the item have
  reached Go, its draft is replaced by Go's version (`drafts/replace`,
  undo history cleared). An edit Go refuses with
  `collection.edited_elsewhere` (made before this window saw the other's)
  is a conflict like the above, with `source: "window"`
  (`drafts.otherWindow`): the banner and the comparison say "another
  PostSonde window". See [Windows](#windows).

Tests: `commands/externalChanges.test.ts`, `components/tabs/ExternalChangeBanner.test.tsx`,
`commands/windows.test.ts`, `lib/lineDiff.test.ts` and the store tests.

Every window of the app loads this page with its own stores and shows the

## Windowing

`components/common/useVirtualRows({ count, rowHeight, overscan, fallbackViewport, pinned, followEnd })` is the one windowing implementation, for lists of fixed-height rows (the collection tree, the message log). It returns a callback `ref` and `onScroll` for the scroll container, the `rendered` indices, the measured `height`, and `scrollToIndex(index, "nearest" | "center" | "end")` and `scrollTo(top)`.

- Rows are absolutely positioned at `index × rowHeight` inside a sizer `count × rowHeight` tall. Only the window plus `overscan` rows each side (default 10) are rendered, plus the `pinned` indices (the focused row).
- The viewport is measured with `ResizeObserver`; until then (and in jsdom) `fallbackViewport` is used.
- Scrolling re-renders only when the rendered range changes, not on every scroll event.
- `followEnd` renders the last rows and scrolls the container to the end before paint, so a live list stays at the bottom without a second render.
- The pure helpers `visibleRange` and `renderedIndices` are tested on their own.

## Message log

`components/messagelog/MessageLog` (WS-05) is the one message log for every streaming connection: WebSocket, Socket.IO, SSE, gRPC streams, GraphQL subscriptions and the local servers. The stream demo in the skeleton shows it ([events.md](events.md#demo)).

```tsx
const [source] = useState(() => new MessageSource({ maxMessages: 50_000 }));
// in a command, or an operation's onItems handler:
source.append(items.map(toLogMessage));
<MessageLog source={source} label="Messages" />
```

- **Source.** `lib/messageSource.ts`, framework-free, so a command can feed it from operation events (`useOperation(…, { onItems })` passes on every data event's items). A message is `{ time, direction: "sent" | "received" | "system", kind, badge?, text?, data?, size?, meta? }`: `kind` is a free string ("text", "binary", "ping", "close", "connected", "error", an SSE event type…), `data` makes it binary, `size` defaults to the UTF-8 length of `text` or `data.length`, and `meta` holds frame details for the detail view (opcode, FIN, masked; [websocket.md](websocket.md)). `time` defaults to when it was appended. Each message gets a `seq`, increasing and never reused. The source keeps the last `maxMessages` (default 50,000) in a ring buffer and counts the dropped ones.
- **Not a reducer store.** At thousands of messages a second an immutable store ([State](#state)) would copy a 50,000-element array on every update. The source is mutable and append-only instead, with its own `subscribe` and an immutable `getSnapshot()` (`version`, `firstSeq`, `nextSeq`, `count`, `dropped`, `kinds`, `startTime`). Give each connection its own source, and remount the log (`key`) when the source changes.
- **Batching.** `append` only queues. The queue is applied on the next animation frame in one step and listeners are notified once, so the log renders at most once a frame whatever the rate. Go already sends at most 20 batches a second per operation ([events.md](events.md#batching-and-throttling)); several connections, or several batches in one frame, still cost one render. While the window gets no frames (hidden), the queue is capped at twice `maxMessages`, and messages beyond that count as dropped. `flush()` applies the queue at once; tests pass their own `schedule` (`src/test/manualFrames.ts`).
- **Filtering.** `components/messagelog/messageView.ts` keeps the shown rows and the search hits as ascending seq lists. A frame's update tests only the new messages and trims dropped ones from the front; a filter change builds a new view in one pass (2–5ms for 50,000 messages in Chromium). A randomized test checks incremental updates against a full recompute.
- **Rows.** Fixed 26px rows through `useVirtualRows`: time (local, with ms; or since the first message with "Relative time"), direction (↑ sent, ↓ received, • system), kind with an optional badge, size, and a one-line preview (whitespace collapsed, cut at 240 characters; binary as hex, or Base64, of the first 48 bytes). Once messages have been dropped, row 0 is a marker: "N older messages dropped".
- **A detail pane, not expanding rows.** Selecting a row (click, Enter or Space) opens the detail pane under the list instead of growing the row, so every row keeps one height and windowing stays simple and smooth. It shows direction, kind, badge, full timestamp, size and `meta`, then the payload: pretty-printed JSON when the text is a JSON object or array (up to 2 MB), else the text, or for binary a hex dump with ASCII (first 64 KB) or Base64 (first 96 KB, wrapped), switched with the pane's **Hexdump | Base64** buttons; a longer payload says how much is shown. Copy buttons copy the text, or all of the hex and Base64 for binary. `renderPayload(message)` lets a protocol show a text payload its own way (return null for the default): the GraphQL subscription log shows a `next` or `error` payload with `GraphqlBody`, the GraphQL response view's summary, errors list with query jumps and marked `data`/`errors` lines ([graphql-subscriptions.md](graphql-subscriptions.md#running-subscriptions-gql-33-gql-34)).
- **Binary view** (WS-06). `binaryToggle` adds a **Hex | Base64** switch to the toolbar that sets how binary previews are shown and which view the detail pane opens with (`initialBinaryView`, default hex); changing it resets the detail pane's own choice. Without it binary is hex, and the detail pane can still switch. The WebSocket editor turns it on. Escape or the close button closes it. A selected message that has been dropped shows "no longer in the log".
- **Follow mode.** The log follows new messages while scrolled to the end. Scrolling up (wheel, keyboard, the scrollbar) or clicking a message pauses it: new messages do not move the view, and when old ones are dropped the scroll offset is corrected so the same messages stay in place. "Jump to latest (N new)" resumes, and so do scrolling back to the end and End. The footer says "Following" or "Paused".
- **Search.** Case-insensitive text, or a regular expression with the `.*` toggle; an invalid one is flagged (`aria-invalid` and its error message) and hides nothing. Text payloads and badges are searched, binary payloads as the hex and the Base64 of their first 1,024 bytes (either view's text matches). Matches are highlighted in the previews. Enter and Shift+Enter (or the arrow buttons) go to the next and previous match, wrapping; the match is scrolled to the centre and following pauses. "Only matching" hides the other messages. Escape clears the search.
- **Filters.** Direction toggles (Sent, Received, System) and a Kind select with the kinds seen since the last clear. `kindToggles` (`{ label, kinds, title? }[]`) adds toggles after the select that hide messages of some kinds (`LogFilter.hiddenKinds`, all shown at first): the WebSocket editor has **Pings** (`ping`, `pong`; WS-09) and **Reconnects** (`reconnect`; WS-10). They apply to messages that arrive later too. Clear empties the source.
- **Accessibility.** `role="grid"` with `aria-rowcount`, a header row of `columnheader`s, and `row`s with `aria-rowindex` and `aria-selected`. Not `role="log"`: a live region announcing thousands of messages a second would flood a screen reader. One row is in the Tab order (the focused row, else the first in view); Up/Down, PageUp/PageDown and Home/End move, and End resumes following. The direction glyph has a visually hidden label. All toolbar controls are labelled; toggles use `aria-pressed`.

Tests render 50,000 messages and check the DOM stays at the window size, and append 10,000 messages between two frames and check the log renders once.

- **Clear.** The Clear button clears the source, then calls `onClear` (the local servers also clear the traffic Go keeps).
- **Copy and save** (DBG-07, see [Copying and saving logs](#copying-and-saving-logs)). ⌘C (Ctrl+C) on the focused row copies that message in full (`messageEntryText`: full time and time since the first message, direction, kind and badge, size in bytes, every `meta` field, then the whole payload, binary as Base64); Shift+F10, the Menu key or a right-click opens its menu (Copy entry, Copy entry as JSON, `messageEntryJson`). The detail pane has **Copy entry** too, and its **Copy payload** is masked the same way (Copy hex and Copy Base64 copy the bytes as received). The toolbar's **Save…** saves the messages the filters show as text or JSON; `saveName` sets the suggested file name (default: the label).

Not yet: saved and resent messages (WS-07), timestamps from Go (the demo stamps arrival time), a byte limit next to the message limit, a resizable detail pane.

## Message composer

`components/messagelog/MessageComposer` is the composer under a message log, shared by the WebSocket editor, the WebSocket server's Clients tab (SSRV-01), the TCP server's Connections tab (SSRV-05), the SSE server's Subscribers tab (SSRV-04, the event data) and the UDP server's Peers tab (SSRV-06). The owner keeps the format and the text (`format`, `onFormatChange`, `message`, `onMessageChange`); the composer does the rest:

- Format switch: `formats` lists the formats offered, text and JSON by default; the TCP server offers text and hex, the WebSocket editor text, JSON, hex and Base64. In hex and Base64 mode the text is checked while typing with `lib/hexBytes.ts` or `lib/base64Bytes.ts` (Go checks again), the bad character is marked in the editor and the message is a link to it, the byte count is shown in the bar, and sending is disabled until it spells at least one byte. `send` gets the text as typed; the owner passes the format on. `extra` adds controls to the bar after the switch (the TCP server's line ending). In JSON mode the text is checked in Go while typing (`useJsonCheck`), the error is marked in the editor (`errorMarker`) and shown as "Line 1, column 6" (a link to the position), and sending is disabled until it is valid. Beautify (the button or ⇧⌘F) goes through `FormatService.BeautifyJSON`.
- `actions`: one or more send buttons `{label, disabled?, title?, send(text)}`. The first is the primary (accent) button and ⌘Enter runs it (`composer.send`, scope `composer`, handled in the capture phase before CodeMirror); a rejected `send` shows its error next to the buttons. The text is kept after sending.
- `readOnly` blocks editing but not sending.

## Tabs

`components/tabs/TabBar` (NAV-01) sits in the shell's `tabBar` slot and shows the open requests and folders: badge (`GET`, `POST`, `GQL`, …, `DIR` for a folder, `tabBadge`), name, close button; the active tab on `--bg1` with an accent underline. The preview tab's name is in italics; pinned tabs come first, at most 140px wide, with a pin where the close button is. `App` renders `TabPanel` in the request pane while a tab is active: the [request editor](#request-editor) for an HTTP request, the TCP editor for a `tcp` request ([tcp.md](tcp.md#ui)), the UDP editor for a `udp` request ([udp.md](udp.md#ui)), the WebSocket editor for a `websocket` request ([websocket.md](websocket.md#ui)), the gRPC editor for a `grpc` request ([grpc.md](grpc.md#ui)), the GraphQL editor for a `graphql` request ([graphql.md](graphql.md#ui)), the request editor with Connect for an `sse` request ([sse.md](sse.md#ui)), the Socket.IO editor for a `socketio` request ([socketio.md](socketio.md#ui)), the [folder settings view](#folder-settings) for a folder, and for other items a placeholder with the item's name, kind and path. With no tab open the request pane shows `NoTabState` (New scratch request and the scratch requests, see [Scratch requests](#scratch-requests)) and the response pane keeps its previous content.

- **State.** `tabs` holds only ids (a tab id is the node id): `order` (pinned tabs first), `pinnedIds`, `activeId`, `previewId` and `closed`; names and badges are read from `collection`, so a rename on reload shows at once. Commands in `commands/tabs.ts`: `openRequest` and `openFolder` (both take `{ preview }`), `activateTab` (also selects the item in the tree), `keepTab`, `setTabPinned`, `closeTabs` (takes `{ remember }`), `closeOtherTabs`, `closeTabsToTheRight`, `closeAllTabs`, `reopenClosedTab`. Closing the active tab activates its right neighbour, else the left one. Reordering touches one store, so the tab bar dispatches `tabs/move`.
- **Preview tab.** A single click (or Space) on a request in the tree opens it in the one preview tab: if a preview tab is open, the new request takes its place in the row and the old one closes (the `onTabClosed` listeners run and its draft is dropped, as for any close, but it is not remembered for reopening). A request that already has a kept tab only activates it. The preview becomes a kept tab when the request is double-clicked or opened with Enter in the tree, when the tab is double-clicked or "Keep open" is chosen in its menu, when its request is first edited (`followTabs` watches the `drafts` store: the preview's draft turning dirty keeps it, so every edit path through `drafts/edit` counts), when it is pinned, and when it is moved (drag or the move keys). Folders (`DIR` tabs) are opened only by Enter or a double-click, so they are never previews.
- **Pinning.** "Pin" / "Unpin" in the tab menu. Pinning moves the tab to the end of the pinned group, unpinning to the start of the unpinned tabs; a drag or move key keeps a tab inside its group (the drop marker too). Close others, Close to the right and Close all leave pinned tabs open. A pinned tab has no close button and the middle button does not close it, but an explicit close does: "Close" in its menu, Delete on the focused tab and ⌘W (Ctrl+W) on the active tab. Its accessible name ends in ", pinned" (the preview's in ", preview").
- **Reopening closed tabs.** Every close through `closeTabs` (close button, middle button, Delete, ⌘W, the menu's close items, closing a project) pushes the closed tabs onto `closed`, each with its index and pinned flag, the most recent last and at most 20 (`MAX_CLOSED_TABS`). A bulk close pushes right to left, so the leftmost comes back first and each lands on its old index. Opening a tab removes its entry. ⇧⌘T (Ctrl+Shift+T, `tab.reopenClosed`) or "Reopen closed tab" in the tab menu runs `reopenClosedTab`: the most recent entry whose item is still in the tree and not open is reopened at its index (clamped to its group), pinned again if it was, activated and selected in the tree; the entries above it (gone or already open) are dropped, and when none is left the list is cleared. Not remembered: a replaced preview tab, and tabs closed because their item disappeared from the tree.
- **`onTabClosed(listener)`** is the hook for work that must happen when tabs close: auto-save registers there to flush the pending save of each closed item. Listeners get `(ids, stores)` synchronously, before the tabs close and before `closeTabs` drops their drafts; a throwing listener is logged and does not stop the close.
- **Mouse.** Pressing a tab activates it; a double-click keeps a preview tab. Dragging it (after 4px) shows an accent drop marker between tabs and moves the tab on release; nothing moves during the drag, so pointer capture is never lost to a DOM reorder; pointer cancel or Escape abandons it. Middle-click or the close button closes (not a pinned tab). Right-click opens the context menu: Close, Close others, Close to the right, Close all (each disabled when it would close nothing), Keep open (preview tab only), Pin or Unpin, Reopen closed tab.
- **Keyboard** (WAI-ARIA tabs, selection follows focus): `role="tablist"` with `tab`s (`aria-selected`, `aria-controls` on the active one) and one `tabpanel` (`aria-labelledby` the active tab). One tab is in the Tab order (roving tabindex). Left/Right move (wrapping), Home/End go to the ends, Delete closes, Shift+F10 or the Menu key opens the context menu. Ctrl+Shift+PageUp/PageDown (⌘ works too) or Alt+Shift+Left/Right (⌥⇧←/→) move the focused tab. The chords of Delete, the menu keys and the moves are registry entries with scope `tabs` (the tab list is marked `data-shortcut-scope="tabs"`); `components/tabs/tabKeys.ts` matches them and they apply only while a tab has focus. On macOS the moves are ⌃⇧PgUp/PgDn or ⇧⌘PgUp/PgDn; elsewhere ⌘ (the Windows or Super key) does not count. The close button is not focusable: a tab may not contain controls.
- **Overflow.** The row scrolls horizontally without a scrollbar; the wheel scrolls it and the active tab is kept in view.
- **Restore.** `useTabsSync` (called by `App`'s project shell) runs `followTabs`: when a project's tree is ready for the first time, the tabs saved for its workspace id are restored (`tabs/restore`: order, active, pinned and preview tabs, and the closed list), dropping ids that are no longer in the tree; a project with nothing saved starts with an empty closed list, so another project's closed tabs are never offered. When the tree reloads, tabs whose node is gone are closed with `closeTabs(…, { remember: false })`. Any change of the tabs state is saved 300ms later, and when the page is hidden, before the project is left, when the project changes or the shell unmounts, in the workspace's local UI state under the key `tabs` (`lib/tabsPersistence.ts`, a `WorkspaceLocalStore`, at most 500 tabs and 20 closed tabs; see Workspace switching; builds before STO-06 used `localStorage` key `postsonde.tabs.<workspaceId>`, which is still read while the local UI state has none) as version 2: `{ version: 2, order, activeId, pinnedIds, previewId, closed: [{ id, index, pinned }] }`. Version 1 data, `{ order, activeId }` without a `version`, still loads, with nothing pinned, no preview and no closed tabs, and is written back as version 2 on the next change; a newer version is ignored. Nothing is saved while no tree is loaded: `applyCurrent` (`commands/workspace.ts`) clears the tree before it closes the old project's tabs, so those tabs come back when the project is opened again.
- **Context menu.** `components/common/ContextMenu` (`label`, `x`, `y`, `items`, `onClose`) is the shared popup menu (the tree's menu reuses it): `role="menu"` with `menuitem`s (`aria-disabled`; an item with `checked` is a `menuitemradio` with `aria-checked` and a check mark, for choices such as the tree's sort order), in a portal on `document.body`, kept inside the window. The first enabled item gets focus; Up/Down (wrapping, skipping disabled items), Home/End and a typed letter move; Enter, Space or a click choose; Escape, Tab, a pointer down outside, window blur or resize close it, and focus returns to where it was.

⌘W (Ctrl+W) closes the active tab from anywhere, pinned or not, and ⇧⌘T (Ctrl+Shift+T) reopens the last closed one (see Keyboard shortcuts).

### Workspace switching

Switching projects (STO-06; the title-bar project switcher, the settings screen's recent list, the welcome screen) goes through `openWorkspaceAt`, `createWorkspaceAt` or `closeWorkspace` in `commands/workspace.ts`:

1. **Leave.** When a project is open (and a different folder is being opened), `leaveWorkspace` (`commands/workspaceLeave.ts`) runs the `onWorkspaceLeaving` listeners and waits for them: `followAutoSave` sends every queued edit and asks Go to write it (`flushAllRequests`), and `followTabs` and `followCollection` save the tabs and the expanded folders now instead of after their debounce. Then it waits until those saves have reached Go (`workspaceLocalIdle`). This happens while Go still has the old project open, so an edit is never sent to the new one. A failing listener is logged and the switch goes on.
2. **Open.** Go opens the new project and returns its `WorkspaceDTO`, which carries the project's saved view state (`uiState`).
3. **Apply.** `applyCurrent` seeds that state (`seedWorkspaceLocal`), clears the tree and closes the old project's tabs (their editors unmount, which cancels their running operations; gRPC calls are cancelled by the tab close, WebSocket and TCP connections are closed by Go on `workspace:changed`), then sets the new project. The tree loads and `followTabs` restores its tabs: order, active tab, pinned tabs, preview tab and closed tabs; `followCollection` restores its expanded folders. The active environment and the cookies are kept by Go in each project's local directory, so they follow the project without UI work.

Local servers (Servers view) are not project-bound: they keep running across a switch and stop when the app quits ([servers.md](servers.md)). The servers saved in the new project's folders are defined (stopped) when its tree loads (`useServersSync` → `syncProjectServers`); the stopped saved servers of the old project are dropped, and its running ones keep running, listed under "This session" with "(other project)", until they are stopped ([servers.md](servers.md#saved-server-configs)).

**Where the view state lives.** `lib/workspaceLocal.ts` holds, per workspace id opened in this window, the folder and the JSON text of each key. `load` reads it synchronously (so restoring needs no extra round trip); `save` updates it and queues `WorkspaceService.SaveUIState({ workspaceId, path, key, value })`, one call at a time in order. Go writes the value to `ui-state.json` in the workspace's local directory ([workspace.md](workspace.md#view-state)), never into the project folder, so switching projects never changes files in a user's repository. A workspace already seeded in this window keeps its in-memory values when it is opened again (they are at least as new); a copy of a project (same id, another folder) replaces them. Saves made in the last 300ms before the app quits may be lost: `pagehide` starts them but the window may be gone before Go answers.

The tab bar's `+` (after the tabs) opens the New scratch request menu; see [Scratch requests](#scratch-requests).

## Console

The console (DBG-06) shows the app log live: requests, connections, dial guard refusals, OAuth exchanges and errors, as the Go services log them with `slog`.

- **Go side.** `cmd/postsonde` builds a `logging.Ring` (the last 2000 records) and passes it to `logging.New` (`Options.Ring`), which tees every record next to the log file, below the redactor: the ring only ever holds redacted text ([privacy.md](privacy.md#the-console)). The ring keeps debug records too, while the file stays at info. Each record carries its source (the `component`/`service` attribute) and, when known, the operation: the `opId`/`conn` and `op` or `domain`+`kind` attributes, or the `netx.WithUserOp` mark of the record's context (`logger.InfoContext(ctx, …)`). `ConsoleService` (`internal/app/services/console`) lists (`List`) and clears (`Clear`) the ring and streams new records as `console:entries` events, batched every 100 ms or 250 records ([events.md](events.md#other-events)).
- **Feed.** `lib/console.ts` has the binding wrappers and `ConsoleFeed`, a framework-free list of records ordered and deduplicated by `seq`, capped at Go's capacity, that also counts the warnings and errors not yet seen. `commands/console.ts` follows Go into the app's feed (`followConsole`: subscribe to the event first, then load the list) while a component calls `useConsoleFeed()`.
- **Toggle.** `AppShell` keeps whether the panel shows as local state. The status bar's Console button (`ConsoleButton`, passed to `StatusBar` as `tools`) and ⇧⌘Y (Ctrl+Shift+Y, `console.toggle`) toggle it. While hidden, the button shows a red count of warnings and errors logged since the panel last showed. The panel sits between the panes and the status bar, 240px high (at most 45% of the column).
- **Panel** (`components/console/ConsolePanel`): level toggles with counts (Debug, off by default; Info, Warnings, Errors), a case-insensitive text filter over the message, source, operation and fields (`consoleView.ts`), and a virtualized list of 22px mono rows (`useVirtualRows`): time, level, source, operation, message, then the other fields; warnings and errors are tinted and the full line is the row's tooltip. The list follows new records until the user scrolls up (or presses Pause); Resume or scrolling back to the end follows again. Copy puts the shown records on the clipboard as text lines (`formatConsoleEntry`), and Save (the download icon) saves them as text or JSON (DBG-07); both are masked in Go first ([Copying and saving logs](#copying-and-saving-logs)). One row is in the Tab order (the focused one, else the first in view); Up/Down, PageUp/PageDown and Home/End move, ⌘C (Ctrl+C) copies the focused record and Shift+F10, the Menu key or a right-click opens its menu (Copy entry, Copy entry as JSON). Clear empties the feed and Go's ring, not the log file. Escape clears the filter field, then closes the panel.
- **Views.** The toolbar's Log / Connections switch shows the connection log in the same panel ([Network activity](#network-activity)).

## Copying and saving logs

Every log and the response timeline can copy one entry, with its full details, and save the whole of what they show to a file (DBG-07): the HTTP response timeline, the [console](#console) and its [connection log](#network-activity), and the [message log](#message-log) of every streaming connection (WebSocket, SSE, Socket.IO, TCP, gRPC streams, GraphQL subscriptions) and of the local servers' traffic.

- **Masked in Go, always.** The UI formats the entry or the log (text or JSON) and hands it to `LogExportService` (`lib/logExport.ts`): `Mask` for the clipboard, `Save` for a file. Go masks every secret the app keeps and the credentials of Authorization lines before the text reaches the clipboard or the disk, so no view, even one that shows a value unmasked (a sent WebSocket message, a URL with a key), can leak one through copy or save ([privacy.md](privacy.md#copied-and-saved-logs)). The toast says when something was masked.
- **Commands.** `commands/logExport.ts`: `copyLogText(text, format, what)` masks, then copies with `lib/clipboard.ts`; `saveLog({ title, fileName, format, build })` builds the log only when saving, then Go shows the native save dialog. Neither rejects; results and failures are toasts. Go's errors: `logexport.invalid_format` and `logexport.invalid_json` (invalid_argument), `logexport.save_failed` (io, not_found or permission_denied; details `path`), `logexport.unavailable` (no save dialog).
- **Controls.** `components/common/LogActions.tsx`: `useEntryMenu(label)` gives a list the entry menu (Copy entry, Copy entry as JSON) with `onKeyDown` (⌘C / Ctrl+C, and Shift+F10 or the Menu key: shortcuts `log.copyEntry` and `log.menu`, scope `log`) and `onContextMenu`; ⌘C leaves the key alone while text is selected, so copying a selection works as usual. `EntryMenuButton` is a copy button that opens that menu (each timeline hop has one). `SaveLogButton` opens a menu of **Save as text…** and **Save as JSON…**. Lists that take the entry keys are marked `data-shortcut-scope="log"`.
- **Formats.** Text: `PostSonde <title>`, the time saved and the entry count, then the entries (one line each for the console and the connection log, separated by blank lines otherwise). JSON: `{ format: "postsonde-log", version: 1, kind, title, savedAt, count, entries }` (`jsonLogDocument`), with `kind` `timeline`, `console`, `connections` or `messages`; entries are the DTOs as Go sent them (a hop, an event, a console record, a connection with its `cause`) or, for messages, `{ seq, time, timeMs, direction, kind, badge?, size?, meta?, text | base64 }`. Both are saved as UTF-8; Go adds the `.txt` or `.json` extension to the suggested name.
- **What is saved.** What the view shows: the records, connections or messages the filters let through, and the whole timeline (every hop, then the events).
- **Language.** A copied entry or a saved log is in the language of the UI, like the view it comes from: its labels, headings and notes are the view's own messages through `t()` (`timelineFormat.ts` and `messagelog/format.ts` serve the Timeline tab and the message log as well as the copy), and its title is the view's. What a program or a bug report relies on stays the same in every language: the JSON format and its keys, `kind`, a message's `direction`, Go's names of trace events and phases (`get_conn`, also in parentheses after the label in the text), the wire text, protocol tokens, Go's error messages (English, see [Localization](#localization)), a message entry's time (`2026-09-19 10:00:00.100`) and exact byte counts. Why not always English: the user saved what they saw, the save dialog and the toasts are in their language anyway, and an English-only copy would need a second set of every label outside the catalogue. For a bug report read by someone else, the JSON format carries the facts without the words; switching the language to English first gives an English text log.
- **Timeline.** `components/response/timelineFormat.ts` formats a hop (`hopText`: timing phases, connection and TLS with the certificate chain, the request as sent with its notes, the response head) and an event (`eventText`); the Timeline tab has **Save timeline…** above the hops, a copy button on each hop, and a roving-focus events table (Up/Down, Home/End, ⌘C, Shift+F10).

## Network activity

The network activity indicator and the connection log (PRV-06) let users check that PostSonde connects only where they asked ([privacy.md](privacy.md#connection-log)).

- **Go side.** `internal/core/netlog` records every dial through the shared dialer, refused ones included; `NetworkService` (`internal/app/services/network`) lists (`List`) and clears (`Clear`) it and sends throttled `network:activity` events ([network.md](network.md#connection-log), [events.md](events.md#other-events)).
- **Feed.** `lib/network.ts` has the binding wrappers and `ConnectionFeed`, a framework-free list of connections merged by id (an older view never replaces a newer one), capped at Go's capacity (ended ones dropped first), with the active count. `commands/network.ts` follows Go into the app's feed (`followNetwork`: subscribe first, then load the list) while a component calls `useNetworkFeed()`; the indicator is always mounted, so the feed is always live.
- **Indicator** (`components/console/NetworkIndicator`), in the status bar before the Console button (both passed to `StatusBar` as `tools`): a dot, an arrows icon and "Idle", or "N connections" in the accent colour with the dot pulsing while any is connecting or open; "via SOCKS5 proxy" (the kinds of proxy, `proxyKind`) while an open connection goes through one, the proxies in its tooltip (NET-06, [network.md](network.md#proxy-indicator)). Under `prefers-reduced-motion: reduce` the dot stays lit without pulsing. Clicking it shows the console on its Connections view, or hides it when that view already shows.
- **Where the log lives.** A view of the console panel rather than a panel of its own: the panel's toolbar has a Log / Connections switch (`ConsoleViews`, with the active count), and `AppShell` keeps the view next to whether the panel shows. ⇧⌘Y and the Console button keep whichever view was last shown. One panel keeps the work area from losing more height, and the two logs are read together (a refused dial is also a warning in the app log).
- **Connections view** (`components/console/ConnectionsPanel`): newest first, one mono row per connection: start time, state (`connecting`, `open`, `closed`, `failed`, `refused`; failed and refused rows tinted), cause (operation kind and ID, or "no user action"), target host:port, remote and local address (with a "via SOCKS5" mark for a connection through a proxy, NET-06), connect time, duration, bytes in and out, and the error code (message in the tooltip). A text filter over target, addresses, cause, state and error code, and an Active only toggle narrow it. Copy puts the shown rows on the clipboard as text lines (`formatConnection`, with the error message), Save saves them as text or JSON (each row with its `cause`), and a focused row (Up/Down, Home/End) copies with ⌘C (Ctrl+C) or opens its menu with Shift+F10, the Menu key or a right-click (DBG-07; all masked in Go first); Clear drops the ended connections here and in Go (open ones stay). Escape clears the filter field, then closes the panel. It is not virtualized: the log keeps at most 500 connections.

## Quick switcher

`components/shell/QuickSwitcher` is the title bar's jump box (NAV-04). A click or ⌘P (Ctrl+P) turns the box into a search field over every request, folder and environment of the project, with the results in a panel under it; focus returns to where it was when it closes.

- **Items.** `buildSwitchItems` (`components/shell/quickSwitch.ts`) flattens the tree depth first (every node, with its folder path `Users / Admin` and its tree badge from `tree/badges.ts`), then the environments. The list is rebuilt only when the tree or the environments change, with the lower-case strings computed once.
- **Matching.** `lib/fuzzy.ts` `fuzzyMatch` is a linear, dependency-free subsequence match: a contiguous occurrence wins (the one at a word start if any), otherwise the shortest window that holds the query. Scores favour word starts (after a space, `/`, `-`, `_`, `.`, or a camelCase hump), the first character and consecutive characters, and cost a little per gap. Spaces in the query are dropped. `searchSwitchItems` tries the name first (a bonus), then folder path and name together, so "admin del" finds Delete user in Users / Admin; the matched characters of both are highlighted (`<mark>`). At most 50 results are shown.
- **Recency.** The switcher remembers the tabs shown most recently (and environments chosen through it) for the open project, 50 at most, in memory only. They are listed first before anything is typed and get a score boost (30, three less per place) while typing.
- **Choosing.** ↑/↓ (wrapping), PageUp/PageDown move; Enter or a click opens a request or folder in a kept tab like Enter in the tree (`openTreeItem`, and its folders are expanded with `revealNode`), or makes an environment active (`setActiveEnvironment`; a failure shows a toast). Escape and Tab close it, and so does focus leaving it.
- **Accessibility.** The field is a `combobox` (`aria-expanded`, `aria-controls`, `aria-autocomplete="list"`, `aria-activedescendant`) over a `listbox` of `option`s whose labels name the kind and folder ("Delete user, DEL, in Users / Admin"); a polite `status` says how many results there are.
- **Commands.** Typing `>` as the first character hands over to the [command palette](#command-palette), as in VS Code: the switcher closes (focus goes back where it was) and the palette opens with the rest of the text as its query. The footer says so. The two stay separate components: the switcher is the title bar's inline box over project items, the palette a modal dialog over app actions.
- **Speed.** `quickSwitch.test.ts` filters a 10,540-item workspace (10k requests in 500 folders, 20 environments) and requires a median under 8 ms per query; it measures about 2.5 ms.

**Chords** (`lib/shortcuts/keys.ts`) are written platform-neutrally: `"Mod+Shift+F"`. `Mod` is ⌘ on macOS and Ctrl elsewhere; `Ctrl` is the Control key everywhere; `Alt` is ⌥. Shown as `⇧⌘F` on macOS and `Ctrl+Shift+F` elsewhere (`formatChord`, `shortcutLabel(id)`); `ariaShortcut(id)` gives the `aria-keyshortcuts` value. The platform comes from `IS_MAC` (`navigator.platform`); every function takes a `mac` argument so tests cover both.

**Matching and keyboard layouts:**

- Modifiers match exactly. AltGr, which Windows reports as Ctrl+Alt, never triggers a `Mod` chord, so typing `@` or `€` on a German layout is safe.
- Letters match by character (`event.key`), so shortcuts follow the layout's labels: ⌘Z is the key that types "z" on QWERTZ, AZERTY and Dvorak. Only when the key types no Latin character (Russian, Greek, or ⌥ on macOS) does matching fall back to the US-QWERTY position (`event.code`): Ctrl+W on a Russian layout is the key that types "ц".
- Symbols (`/`, `,`, `?`) match by character and ignore Shift, because many layouts need Shift for them (German `/` is Shift+7). A symbol chord therefore never names Shift. A non-Latin character falls back to the US position (Russian "б" is the Comma key, so Ctrl+б opens settings).
- Named keys (`Enter`, `PageUp`, `ArrowLeft`, `F10`, `ContextMenu`) match `event.key` with exact Shift.

**Running them** (`commands/shortcuts.ts`): `installShortcuts(stores)` adds one `keydown` listener on `window` in the capture phase, so it runs before components and CodeMirror. For each key press, `handleShortcutKeyDown`:

1. ignores events already `defaultPrevented`, IME composition (`isComposing`, keyCode 229) and key presses inside a shortcut recorder (`data-shortcut-scope="record"`, the Shortcuts settings page), so a chord can be recorded even when it is a shortcut;
2. steps aside when focus is inside an element marked `data-shortcut-scope` (`tabs`, `tree`, `table`, `editor`, `composer`, `graphql`) and a shortcut of that scope has the same chord: the component or CodeMirror handles it (⌘Enter in a table adds a row, ⌘/ in an editor toggles a comment);
3. in a text field (input, textarea, select, contenteditable such as CodeMirror) runs only chords with ⌘ or Ctrl, so `?` types;
4. inside a dialog (`data-shortcut-scope="dialog"`) runs only shortcuts marked `inDialog` (the help toggle);
5. swallows key repeat without running the shortcut again (holding ⌘W does not close every tab);
6. swallows a placeholder's chord and does nothing, so the chord already behaves the same when the feature lands (⌘Enter no longer inserts a blank line in an editor);
7. otherwise calls the handler bound to the id, then `preventDefault` and `stopPropagation`. With no handler bound, or a handler that returns `false`, the key press goes on untouched.

The `request` scope (undo and redo, NAV-07) is the one exception: no element is marked `data-shortcut-scope="request"`, and its chords are handled by a second `window` listener in the bubble phase (`commands/undoRedo.ts`), after CodeMirror and the components. So the global ⌘Z of an Undo-delete toast still runs first when focus is not in a text field; `registry.test.ts` lists `request.undo > collection.undoDelete` as an intended override.

Handlers are bound by id: `bindCommandShortcuts` binds the ones that are plain commands (`tab.close`, `tab.reopenClosed`), and components bind the ones that need local state with `useShortcut(id, handler)` (`components/shell/useShortcut.ts`): `AppShell` (sidebar, settings screen, `collection.filter`, `console.toggle`), `EnvironmentSwitcher`, `ShortcutHelp`, `ToastHost`, the status bar's `SecretsStatus` (`secrets.lock`, ⌥⌘L, while the encrypted secrets are unlocked; docs/privacy.md#encrypted-secrets), and the sidebar's `useNewItemDialog` (`request.new`). The latest binding of an id wins.

**Adding a shortcut:** add an entry to `SHORTCUTS` with its label as a message key (`labelKey: "lib.shortcuts.action.<id>"`, in `i18n/en/lib.ts`; see [Localization](#localization)), then bind a handler (global) or match it in the component with `matchesShortcut(event, id)` and mark the component's root with `data-shortcut-scope` (scoped). Text is looked up where it is shown: `t(def.labelKey)` (or `shortcutName(def)`), `shortcutGroupLabel(group)`, `scopeLabel(scope)` and `scopePlace(scope)`; key names in `formatChord` come from `lib.keys.*` (macOS symbols are not text). A global one bound only at times gets a `whenKey` message (what it needs, shown by the palette while it is unbound); one whose keys belong to CodeMirror's own keymap is `fixed` (not remappable). Never compare against `def.keys` directly: `shortcutKeys(def)`, `shortcutChords`, `matchesShortcut` and the label functions read the chords in effect, custom ones included. `registry.test.ts` fails when two shortcuts of one scope share a chord on either platform, and when a scoped chord shadows a global one that is not in its list of intended overrides; `ShortcutHelp.test.tsx` checks the overlay lists every entry; `commands/palette.test.ts` checks that every entry is listed by the palette and runs from it.

**Help overlay** (`components/shell/ShortcutHelp`): ⌘/ (Ctrl+/), or `?` outside text fields, opens a modal dialog listing the registry by group, with a filter field (label, scope or keys), scope notes and "Coming soon" on placeholders. It shows the chords in effect, custom ones included. It is the shared `Dialog` (560px, no footer): focus moves to the filter and stays inside, Escape, the close button or a click on the scrim close it, and focus returns to where it was (see Dialog).

### Command palette

`components/shell/CommandPalette` (NAV-05) runs any action of the shortcut registry by name. Every registry entry is an action (the registry is the one list of app actions); only `palette.open` itself is left out (`NOT_IN_PALETTE`). ⇧⌘P (Ctrl+Shift+P, `palette.open`; free on every platform and in the registry) or `>` typed first in the [quick switcher](#quick-switcher) opens it; `openCommandPalette(query)` (`commands/palette.ts`) is how other components ask.

- **Frame.** The shared `Dialog` (600px, title "Commands", no footer): focus moves to the field and stays inside, Escape, the close button or the scrim close it, focus returns to where it was. Global shortcuts do not run inside it (dialog scope).
- **Items** (`paletteItems`): the label, where it applies (the scope label) and its chords in effect, as `<kbd>`. `fuzzyMatch` (`lib/fuzzy.ts`, as the quick switcher) over the label, then over group, scope and label together; matched characters highlighted. Available actions first, then by score. Before anything is typed, the actions run most recently from the palette (8, in memory, this session) come first, then registry order.
- **Availability** (`actionAvailability`), decided for the element that had focus when the palette opened: a global action is available while a handler is bound to its id (`Send request` only while a request editor is mounted); a scoped one while that element is inside its scope (`data-shortcut-scope`, or for `request` inside `data-edit-history` but not in a code editor). An unavailable action is still listed, after the others, as a disabled option (`aria-disabled`, dimmed) with the reason in place of its scope: the definition's `when` text ("Open a GraphQL request first"), "Only in a GraphQL query editor" (GraphQL Fill fields), "Coming soon" for a placeholder. Choosing it does nothing.
- **Running** (`runPaletteAction`). Enter or a click closes the palette; once the dialog has given focus back, the action runs there. A global action calls its bound handler, exactly as its key would; a handler that returns `false` ("nothing to do now", such as Switch environment without environments) shows a toast. A scoped action presses its main chord (in effect, so a remapped one presses the new chord) on the element that had focus, as a synthetic `keydown` (`chordEventInit`): the component, or CodeMirror for the editor's own keymaps, handles it as the real key, and the window listener steps aside because the scope defines the chord. So every scoped shortcut, including ones added later, runs from the palette without code of its own.
- **Keyboard and ARIA.** The field is a `combobox` (`aria-expanded`, `aria-controls` the `listbox`, `aria-autocomplete="list"`, `aria-activedescendant` the highlighted `option`); ↑/↓ (wrapping), PageUp/PageDown move, Enter runs. Each option's accessible name has the label, keys and scope or reason; a polite `status` says how many commands are available and, on a disabled one, why.
- **Tests.** `commands/palette.test.ts` iterates the registry on both platforms: each action is listed and available where it applies, and running it calls its handler (global) or delivers its chord where focus was (scoped). `CommandPalette.test.tsx` covers the dialog, keyboard, a disabled Fill fields, Fill fields in its scope with a custom chord, and CodeMirror's Find.

### Custom shortcuts

The settings screen's **Shortcuts** page (UI-07, `components/settings/ShortcutSettings`) lists every registry entry by group with its current chords and a filter (label, group, scope or keys).

- **Change** turns the chord into a recorder (a focused button marked `data-shortcut-scope="record"`, so the window listener leaves every key to it): the next key press that is not only a modifier is the new chord (`chordFromEvent`, `lib/shortcuts/keys.ts`, which writes it as the registry does: `Mod` for ⌘ on macOS and Ctrl elsewhere, letters by position when the layout types no Latin letter, symbols without Shift). Escape, Tab or leaving the button cancels.
- **Checks** (`checkShortcutBinding`, `lib/shortcuts/registry.ts`). Refused, with the reason under the row, and still recording: another shortcut of the same scope on that chord ("⌘W is already “Close tab”"), a key the OS, the window or every text field keeps (`RESERVED_CHORDS`: ⌘Q, ⌘H, ⌘M, ⌘R, ⌘Space on macOS; Alt+F4 elsewhere; copy, paste, cut and select all everywhere), a plain character without ⌘, Ctrl or ⌥ (it would stop typing), and the fixed shortcuts (CodeMirror's Find, Select next occurrence, Toggle comment). Saved with a warning: a chord a shortcut of another scope takes where this one applies (a global chord that is Find inside code editors), and a global chord without ⌘ or Ctrl, which does not run in text fields.
- **Saved** at once with `applySetting` as `settings.shortcuts`, the whole map (`{"request.send": ["Mod+Shift+K"]}`), in `settings.json` ([settings.md](settings.md)): app settings, never the project. Recording an action's own default removes its entry. **Reset** removes one entry, **Reset all** saves `{}`. The default chords are shown next to a changed one.
- **Applied** by `useShortcutOverridesSync` (called by `App`): whenever `settings.shortcuts` changes (the settings load at startup, the page, a hand edit of the file), it calls `setShortcutOverrides`. The registry keeps the overrides in memory, drops unknown ids, fixed shortcuts and chords it cannot parse, and every key match, label, `aria-keyshortcuts`, conflict check and the palette read the chords in effect at once. An override replaces all of a shortcut's chords. `useShortcutOverrides()` re-renders a component when they change: the help overlay, the palette and `AppShell` (so tooltips in the shell show the new keys) use it.
- **Not remappable:** the chords CodeMirror handles itself. `editor.*` entries are `fixed`; request undo and redo (`request.undo`, `request.redo`) can be remapped outside code editors, while inside them CodeMirror's history keeps ⌘Z and ⇧⌘Z.

### Focus mode

Focus mode (UI-09) hides the icon rail, the sidebar and the console panel, so the tab bar, the request and the response fill the window; the title bar and the status bar stay. ⇧⌘↩ (Ctrl+Shift+Enter, `view.focusMode`) or the palette's "Toggle focus mode" turns it on and off; while on, the status bar shows a **Focus mode** button (accent, `aria-pressed`) that ends it.

- **Restores the layout exactly.** Focus mode is a flag (`AppShell` local state) on top of the layout rather than a change of it: `settings.sidebarCollapsed`, the sidebar's view, whether the console shows and its view are not touched. The rail and the sidebar get the `hidden` attribute and the console panel sits in a `display: contents` slot that is hidden, so nothing unmounts: the sidebar's filter, the console's filter and scroll position are there when it ends.
- **Per session.** Not saved: a new window, or the project shell opening again, starts without it. It is a way of working on one request for a while, not a layout preference, and a saved one would open the app with the navigation hidden.
- **Leaving it by asking for what it hides.** The sidebar toggle (⌘B) ends focus mode and shows the sidebar (also when it was collapsed); the console toggle (⇧⌘Y) and the network indicator end it and show the console; Filter the collection tree (⇧⌘E) and the settings screen (⌘,), which needs the rail to go back, end it too. From the settings screen, ⇧⌘↩ goes back to the work area in focus mode.
- **Focus.** Turning it on while focus is in a part it hides moves focus to the main column (`tabIndex=-1`, no ring), so the keyboard is not stranded on a hidden element; the status bar button hands focus to the main column when it ends focus mode.

**Native menus and web views.** Checked in Wails v3.0.0:

- **macOS:** Wails installs its default application menu, whose File > Close has ⌘W (and Quit ⌘Q, Minimise ⌘M, Reload ⌘R, the Edit items). WKWebView gives the page the key press first and runs the menu's key equivalent only when the page did not `preventDefault` it (WebKit's behaviour for key equivalents; still to be confirmed in a built app window). So ⌘W closes a tab, and it is taken even with no tab open, or the menu would close the window and quit the app. On the welcome screen (no shell, no shortcuts) ⌘W still closes the window. None of the other chords are in the default menu.
- **Windows:** no application menu is attached to the window (`UseApplicationMenu` is off) and WebView2's browser accelerator keys are disabled by Wails, so Ctrl+N, Ctrl+W, Ctrl+F and friends reach the page with no browser action.
- **Linux:** the default menu is only built on macOS, and GTK menu accelerators are not wired in this Wails version, so key presses reach WebKitGTK and the page.

If a custom application menu is added later, its accelerators must not reuse these chords, or they must call the same commands.

## Request editor

`components/editor/RequestEditor` (HTTP-01) is the active HTTP request's tab content: the URL bar (method picker, URL field, Send), then the sub-tabs **Params**, **Headers**, **Body**, **Auth**, **Tests**, **Examples**, **Settings**, **Notes** ([Notes](#notes)) and **Code** ([Snippet panel](#snippet-panel)). `TabPanel` mounts it with `key={id}`, so each request starts with fresh local state.

- **Loading.** `useRequestDraft(id)` (`commands/`) loads `CollectionService.Request(id)` (pending edits included) into a draft with `loadRequestDraft` the first time the tab shows the request. The draft stays in the `drafts` store while the tab is open, so switching tabs back does not load again; closing the tab drops it (`closeTabs`). Nothing is shown while loading; a failed load shows the error with "Try again".
- **Saving.** Every change goes through the auto-save pipeline ([collection.md](collection.md#auto-save)): `useAutoSave(id).edit(patch)` patches the draft and sends the whole DTO, so members the editor does not touch (`body`, `auth`, `settings`, `extra` objects) go back unchanged. The URL field and the tables show the draft. A method change goes through `setRequestMethod` (`commands/requestEditor.ts`), which also dispatches `collection/setMethod` so the tree and tab badges follow before the tree reloads.
- **Method picker** (`MethodPicker`, HTTP-01, HTTP-02): a native `<select>` styled as a coloured method label (`--m-*` through `methodBadge`: GET, POST, PUT, PATCH and DELETE have their tokens; HEAD, OPTIONS and custom methods use the neutral `--m-dir`). It offers GET, POST, PUT, PATCH, DELETE, HEAD and OPTIONS, then **Custom…**. A method the file already has that is not offered (e.g. `PROPFIND`) is shown as the current value and stays in the list while the editor is open, so it is never changed unless another method is picked, and picking it again restores it; so does every custom method entered while the editor is open. A native select was chosen over a custom menu: keyboard and screen-reader support come for free.
  - **Custom…** replaces the select with a text field (`aria-label="Custom method"`, focused, holding the current method when it is a custom one). Enter saves the text when it is a method (`methodProblem`: an RFC 9110 token, not `CONNECT`, the rule of Go's `request.Method`); otherwise the field stays, marked `aria-invalid` in `--bad` with the reason as tooltip and description. Blur saves a valid method and drops anything else; Escape cancels. Both Enter and Escape return focus to the select. Nothing but a valid method is ever saved.
  - **Case:** methods are saved and sent as typed. Another spelling of a registered method (`get`, `Post`; `canonicalMethod`, the mirror of `request.CanonicalMethod`) shows a warning mark before the method, "Methods are case-sensitive: get is sent as typed, not as GET, and servers may reject it.", as tooltip and as the select's `aria-describedby`. The tree and tab badges upper-case the label (`GET`), and show at most 5 characters (`PROPF`), unchanged.
- **URL field** (HTTP-04): the shared `CodeEditor` with `singleLine` (`singleLine.ts`): no gutters, search or Tab indent (Tab moves focus), `{{variables}}` as chips (see Template variables; found with `lib/templateSyntax.ts`, a TypeScript scanner that follows the Go parser in `internal/core/template`: whitespace inside the braces, `\{{` escapes, `{{{`), and a placeholder. Enter and Shift+Enter do nothing; ⌘Enter stays the global Send shortcut because the field is not marked `data-shortcut-scope`. Line breaks in typed, pasted or dropped text are removed, and pasted text is trimmed line by line and joined, so a URL copied across lines arrives whole. When the parent sets new text (after a table edit), `CodeEditor` replaces only the part that differs, so the caret and selection outside it stay put.
- **URL ↔ Params sync** (HTTP-04, HTTP-06): `useUrlParamsSync` turns every URL edit into one `edit({ url, params })` and every table edit into one `edit({ params, url })` (only the fields that changed), so auto-save sends once per edit and nothing loops: the other side is computed, not echoed back. The rules live in `lib/urlParams.ts`:
  - **Splitting.** Outside `{{…}}`: the fragment starts at the first `#`, the query at the first `?` before it; entries split on `&`, key and value on the first `=`. A `?`, `&`, `=` or `#` inside a variable never splits (`{{baseUrl}}/p?q={{a&b}}` is one entry). Empty entries (`?`, `&&`, a trailing `&`) make no rows; a key without `=` is a row with an empty value; repeated keys are separate rows.
  - **Encoding.** Nothing is decoded or normalized: rows hold the text as written (`%20` and `+` stay as they are), so a pasted URL round-trips byte for byte. When a row is written into the URL, only what would break the query is percent-encoded: `&` and `#`, and `=` in a key (outside variables). A row whose written form equals the URL's entry keeps its own text, so a row value `a&b` and the URL's `a%26b` agree.
  - **Rows → URL** (`paramsToUrl`): the query is rebuilt from the enabled rows that have a key or a value, in order, as `key=value`, or `key` when the value is empty; entries that still match keep their exact text (`key=`). The fragment stays last; with no such rows the `?` goes. If the query already says the same, the URL is left untouched. Disabled and blank rows stay in `params` only (the file's `url` holds the enabled query, docs/file-format.md). Editing a description does not change the URL.
  - **URL → rows** (`urlToParams`): disabled and blank rows are not in the URL and keep their places. The rows in the URL are paired with the parsed entries in order, preferring the same key and value, then the same key; rows and entries left between two pairs are paired by position, so editing a key in place keeps its row. A paired row takes the entry's key and value and keeps its description, enabled flag and `extra`; unpaired rows are deleted; unpaired entries become new rows right after the row before them (before the first row in the URL, or at the end when there is none). When nothing changed the same array comes back and only `url` is saved.
  - A file whose `url` and `params` disagree (a hand edit) is shown as it is; the next edit on either side brings them in step.
- **Path variables** (HTTP-05): `lib/pathParams.ts` finds the `:name` and `{name}` placeholders in the URL's path (`findPathParams`, a mirror of Go's `request.PathParams`, tested with Go against `internal/core/request/testdata/path_params.json`; rules in [http-client.md](http-client.md#path-parameters)). Placeholders are coloured `--tk-arg` in the URL field (`pathParamHighlight.ts`, added to the view from `onReady`, so other single-line fields do not get it).
  - **Table.** When the URL has placeholders, the Params tab shows a "Query params" heading over the query table and, below it, "Path variables": a `KeyValueTable` with `fixedKeys`, one row per distinct name in URL order. Names come from the URL and are read-only; there is no toggle, empty row or delete (Go ignores `disabled` on these rows). Values and descriptions are edited and auto-saved as `pathParams` (`edit({ pathParams })`), as plain text: Go expands `{{variables}}` and percent-encodes the value when sending. The value placeholder reads "required", since Go refuses to send a placeholder without a value. The Params badge counts the enabled query rows plus the path variables.
  - **Following the URL** (`syncPathParams`): every URL edit also computes the path rows, and saves them in the same patch when they changed. A name keeps its row (description and `extra` included; the first row when a hand-edited file repeats a name), a new name gets an empty row, and rows whose names left the URL are dropped from `pathParams` and put in `drafts.pathParamStash` (`drafts/stashPathParams`, by request and name). When the name comes back (an undo, retyping `:id`), its stashed row returns. The stash is not saved and is dropped with the draft, like `bodyStash`. Renaming a placeholder (`:id` → `:userId`) is a new name with an empty value; the old value waits in the stash.
  - The file keeps rows only for the names in its `url`. A file whose rows disagree with its URL is shown with the rows the URL implies (nothing is saved until the next URL or path-table edit).
- **Send** (HTTP-20) and ⌘↩ (`request.send`, bound with `useShortcut` while the editor is mounted, so it works in the URL field, the tables and the body editor) send the request through `commands/httpSends.ts`: `sendRequest(stores, id)` first waits for the request's queued auto-save edits to reach Go (`waitForQueuedEdits` in `commands/autosave.ts`; Go sends its view of the request, pending edits included, not the file on disk), then starts an `http` operation (`lib/http.ts`, `HTTPService.Send`). While it runs, Send becomes **Cancel** (`cancelRequest`, i.e. `OpsService.Cancel`) and ⌘↩ does nothing. One `HttpSend` slot per request lives outside React (`httpSends()`, read with `useHttpSend`), so switching tabs keeps a running send and its response; closing the tab cancels the send and drops the response. Read-only requests can be sent. The arrow joined to Send (**Repeat…**, `aria-haspopup="dialog"`) opens `RepeatDialog.tsx` (HTTP-27): "A number of times" (Times, Wait between in seconds) or "At an interval" (Every in seconds, at least 0.1; Stop after, empty for until stopped), with errors under the fields and Start disabled until they are valid; Enter starts, Esc closes, and it opens with the last run's options (`HttpSend.runOptions`). `repeatRequest(stores, id, options)` flushes the edits and starts an `http.repeat` operation (`HTTPService.Repeat`) in the same slot; while it runs Send is **Stop**. The slot's `run` state (`HttpRunState`) keeps the last 1,000 results and counts all of them (responses, failed, 4xx/5xx or failed tests, total/min/max time).
- **SSE requests** (SSE-01): an `sse` request has an HTTP request's members, so `TabPanel` shows it in this editor too (method, URL, Params, Headers, Body, Auth, Settings; no Tests: an event stream is not checked, and assertions a file carries are kept as they are). Its button is **Connect** instead of Send (`ConnectButton`; ⌘↩ too), which opens the event stream through `commands/sseStreams.ts` (`connectStream(stores, id)`: the queued edits reach Go first, then an `sse` operation, `SSEService.Connect`), and **Stop** while it runs (`stopStream`, `OpsService.Cancel`). One `SseStream` slot per request (`sseStreams()`, read with `useSseStream`) holds the stream's state and its `MessageSource`, outside React: switching tabs keeps the stream running and its events; closing the tab stops it and drops them. A cURL paste is not taken over in an sse request's URL field. Its Settings sub-tab (`RequestSettings` with `stream`) adds **Reconnect** (SSE-03): the switch "Reconnect with Last-Event-ID", the attempts in a row (empty: 5, 0: no limit) and the delay (empty: 3000 ms), stored as `settings.reconnect` and left out of the file when nothing is set (`reconnectPatch`). The response pane (`SseResponsePanel`) shows a reconnect wait in the status line with a countdown ("reconnecting in 2.4 s · attempt 1 of 5") and the reconnections made, offers **Resume** after a stream with a last event ID ended (`resumeStream`: the first connection sends Last-Event-ID, the log and counts carry on), and has the tabs Events, **Merged** (`SseMergedView`, SSE-04: the events' data joined into one text by `lib/sseMerge.ts`, with an event-type filter, Auto / Data as is / JSON field extraction, joining with nothing or new lines, Copy, following the stream live) and Headers. [sse.md](sse.md#ui).
- **Settings** (HTTP-21) is `RequestSettings.tsx`: the request's own timeout in milliseconds, saved as `settings.timeoutMs`. Empty uses the default timeout of the settings screen (`network.defaultTimeoutMs`, named in the placeholder, "default (30 s)"), `0` means no timeout, anything else but whole milliseconds up to 24 hours is an error under the field and is not saved. A line under the field says what the request will do. With a filter set it searches the filtered result, and ⌘F in the filter box opens it too.
  - **Filter** (HTTP-36, `components/response/ResponseFilter.tsx`, `lib/responseFilter.ts`): a bar above the body (any non-empty text body; not a hex dump) with a **JSONPath / XPath** switch and the expression box. The syntax follows the body: JSONPath for JSON, XPath for XML and HTML, and for text what it starts with (`<` means XPath); picking the other one overrides it. Typing is debounced (250 ms), then `HTTPService.FilterBody` evaluates the expression in Go on the bytes received, not on the clipped text ([http-client.md](http-client.md#response-filter-http-36)); a newer keystroke cancels the call. While a filter is set, the body area shows the result in a read-only editor (JSON highlighted, XML indented and highlighted, a scalar as text), with a **Values / Paths** switch for the nodes' paths; the Pretty / Raw / GraphQL switch is hidden. Next to the box: "3 matches", "No matches", "Number" or "Filtering…" (the previous result stays, dimmed, meanwhile). A bad expression turns the box red and says what is wrong "at position N" (a link that selects that character in the box) with the expression below, the character marked; a body that is not JSON or XML says so with its line and column. A body Go no longer keeps is filtered as shown, with a note. **Esc** in the box or the × clears the filter and the body comes back. **Enter** (or leaving the box) remembers an expression that gave a result among the request's **recent expressions**, offered as the box's suggestions (a `<datalist>`, per syntax, at most 8). With the `filter` prop (`{workspaceId, requestId}`, which `HttpResponsePanel` passes) the filter is the request's: the syntax picked, the expression and the recent ones are kept in the workspace's local UI state under `response.filters` ([workspace.md](workspace.md#view-state)), saved 500 ms after a change and when the view goes, and the next response of the request (or the next session) is filtered the same way. Without it the filter lasts as long as the view.
- **Sub-tabs:** `role="tablist"` inside the tab panel; Left/Right (wrapping), Home and End move and select. The selection is kept per request in `drafts.subTabs` (`drafts/setSubTab`), not on disk, and dropped with the draft.
- **Undo and redo** (NAV-07): ⌘Z and ⇧⌘Z (Ctrl+Z, Ctrl+Shift+Z or Ctrl+Y) anywhere in the editor, kept across tab switches; see [Undo and redo](#undo-and-redo).
- **Read-only.** When the item (`newer_version`, `symlink`, …) or the project (`collection.readOnly`) is read-only, a notice with the reason sits above the URL bar; the method picker is disabled (without Custom…), the URL field is read-only (selectable, not editable) and the tables are read-only (no empty row, no delete). Nothing is sent to Go.

- **cURL paste** (IMP-01, `components/editor/curlPaste.tsx`): text pasted into the URL field that `looksLikeCurl` accepts (`lib/curl.ts`: an optional shell prompt, `curl` or `curl.exe` bare or with a path, then an argument) is taken in the capture phase, before the single-line field joins its lines, and never reaches the field. `pasteCurlIntoRequest` asks `ParseCurl`. A command with an error changes nothing and shows a toast with the first error and "Open in Import cURL" (the dialog, with the text). Otherwise `replaceWithCurl` (`commands/curlImport.ts`) replaces the method, URL, params, path params, headers, body, auth and the http settings (timeout, redirects and their method and Authorization handling, TLS verification) with `importPatch`; the other settings, the name, the description and unknown members stay. It is **one** `editRequest` with `history: "separate"`, so ⌘Z in the editor panel undoes it, and a toast says so, lists up to three warnings ("And N more.") and offers **Undo**, which undoes exactly that edit and does nothing once another edit followed. Info diagnostics are not listed. Read-only requests paste as usual.

### Body editor

`components/editor/BodyEditor` (HTTP-10…12) is the Body sub-tab. Commands in `commands/body.ts`; the JSON tools run in Go ([json-tools.md](json-tools.md)).

- **Mode picker:** a radio group (native radios styled as pills) with None, Raw, Form URL-encoded, Multipart form and Binary file, all editable (`EDITABLE_BODY_MODES`). A mode of a newer PostSonde is shown by name (`“graphql2”`) with a note that it stays in the file exactly as it is; it can only be picked again while the body is (or was, this session) in it.
- **What is saved.** A mode change goes through `setBodyMode`, which saves a body with only the new mode's members: None is written as `{"mode": "none"}`, a new Raw body as `{"mode": "raw", "type": "json"}`. The body left behind is kept in `drafts.bodyStash` (by request and mode) and comes back when that mode is picked again, so raw text survives a detour through None, and a multipart body survives a detour through Raw, while the tab is open. The stash is not saved and is dropped with the draft: close the tab on None and the old text is gone from the file, as the file format says (members of other modes are left out). Unknown body members (`extra`) stay across the known modes; those of an unknown mode belong to it and leave with it.
- **Form URL-encoded** (HTTP-13): a `KeyValueTable` ("Form fields", description column shown, no suggestions) bound to the body's `fields` through `useKeyValueRows`, so rows keep their `extra`; every edit, new row, toggle and delete goes through `setFormFields` as an auto-saved edit. Rows are saved as typed, plain text: Go encodes them when sending ([http-client.md](http-client.md#form-bodies)), so the editor never shows `%XX`. A new form body starts with no fields (`{"mode": "urlencoded"}`).
- **Multipart form** (HTTP-14, `components/editor/BodyFiles.tsx`): a `KeyValueTable` ("Multipart parts", description column shown) bound to the body's `parts` through `usePartRows` (`partRows.ts`, which keeps each part's `file`, `contentType` and `extra` by row id through table edits). At the end of every part's value cell (`valueActions`) sit a Content-Type field and a Text/File select. A text part edits its value in the cell; a file part's value cell is replaced (the table's `valueCell` prop) by a file chip: icon, base name, size (hidden when the cell is narrow; the tooltip has the absolute path and size), a warning and "missing" when there is no file at the path, and **Choose…**. Picking File, or Choose…, opens the native file dialog through `choosePartFile` (`WorkspaceService.PickBodyFile`); a cancelled dialog changes nothing, so a part only becomes a file part with a file. Picking Text drops the file and keeps the name, Content-Type and description. The Content-Type field's placeholder is the type the part's file name implies (`fileMediaType`, the table shared with Go); a text part's is "Content-Type" (none is sent). A dialog that cannot be shown is reported under the table. A new multipart body starts with no parts.
- **Binary file** (HTTP-15): the file chip with Choose… (`chooseBodyFile`, "No file chosen" until one is), a Content-Type field saved as the body's `contentType` override (placeholder: the type implied by the file name) and a line saying the file is streamed from disk and only its path is stored.
- **File chips** ask Go about the stored path with `useBodyFile` (`WorkspaceService.BodyFile`) whenever the path changes or the chip mounts, so a restored file shows up; the answer of a dialog is remembered so the chip shows at once. The UI never reads the files. Paths are stored as Go returns them: relative to the project root when the file is inside it, else absolute ([file-format.md](file-format.md)).
- **No conversion between modes.** Switching Raw ⇄ Form URL-encoded does not turn JSON into fields or fields into text: each mode keeps its own content through the stash above, and a mode never used starts empty. Converting guesses (nested JSON, duplicates, types) and would silently rewrite what was typed.
- **Raw language:** a native select, JSON, XML, HTML, Text or YAML (`type`); changing it keeps the text. A type the file has that is not offered is shown as is. Only JSON is highlighted: `@codemirror/lang-xml`, `lang-html` and `lang-yaml` (or `@codemirror/legacy-modes`) are not dependencies, so XML, HTML and YAML are plain text until one is added.
- **Text:** a `CodeEditor` bound to `text`; every change is an auto-saved edit. Text is saved as typed, valid or not.
- **JSON check:** `useJsonCheck` (`commands/`) calls `FormatService.ValidateJSON` 300ms after typing pauses (not for other languages or blank text), cancelling a check still running. There is no TypeScript check: Go is the one validator. The result sets the error marker (`components/editor/errorMarker.ts`, a StateField added to the view with `StateEffect.appendConfig` from `onReady`, since `@codemirror/lint` is not a dependency): a wavy underline on the offending character (the last character when the text ends too early), a tinted line and the message on hover. The marker moves with edits until the next result replaces it, so it does not blink while typing. Below the editor a status line shows "Line 4, column 21" (a button that moves the cursor there) and the message.
- **Beautify and Minify** (JSON only): buttons in the toolbar, and ⇧⌘F (Ctrl+Shift+F) for Beautify, bound with `useShortcut` while a JSON body is shown and editable. `formatRequestBody` sends the text to Go (2-space indent) and saves the result as an edit; the editor replaces its text, so ⌘Z undoes it. Invalid JSON is not changed: the marker is set and the cursor moves to the error. A result is dropped when the text changed while Go worked.
- **Read-only:** radios, select and buttons disabled, the editor read-only, the shortcut not bound; the marker still shows.
- **Body examples** (HTTP-17, `BodyExamples.tsx`, commands in `commands/bodyExamples.ts`): a bar above the toolbar. Without examples it is one button, **Add example**, which names the current body "Default" and adds a copy of it as "Example 2", made active. With examples: a select of their names (the one picked is active: its body is the request's `body`, the one sent), the active example's name as an input, **Add** (a copy of the current body, made active) and **Delete** (the active example; the one before it, else after it, becomes active; deleting the only example leaves its body as the request's unnamed body). Switching (`selectBodyExample`) moves the bodies between `body` and `bodyExamples` in one auto-saved edit, so ⌘Z switches back, and clears `drafts.bodyStash` (`drafts/clearBodyStash`), which belongs to the body being left. The file shape is in [file-format.md](file-format.md#body-examples).
- **SOAP helper** (HTTP-18, `SoapHelper.tsx`, `commands/soap.ts`): **SOAP…** in the toolbar opens a panel with the version (SOAP 1.1 or 1.2), the action (may hold `{{variables}}`) and **Apply envelope**. `applySoapEnvelope` sends the raw body text (or "" for another mode) to `FormatService.SOAPEnvelope` and, in one edit, makes the body raw XML with the envelope (a body of another mode is stashed as a mode switch would) and sets the header rows (`withSoapHeaders`: Content-Type, and SOAPAction for 1.1; 1.2 removes SOAPAction). When the body or headers changed while Go worked, nothing is applied. The version and action fields are not saved: the request is an ordinary one afterwards ([http-client.md](http-client.md#soap-helper)).

### Auth editor

`components/editor/AuthEditor` (AUTH-01…06, AUTH-15…19) is the Auth sub-tab, laid out as a two-column grid (140px labels): the type picker, then the type's fields. Commands in `commands/auth.ts`, helpers in `lib/auth.ts`; what is sent and where secrets are kept is decided in Go ([auth.md](auth.md)).

- **Type picker:** a radio group styled as a segmented control, in this order: Inherit, None, Bearer, Basic, Digest, API key, then JWT, OAuth 1.0, OAuth 2.0, AWS Signature, Hawk and Netrc. A type of a newer PostSonde is shown by name with a note and stays in the file as it is; it stays offered (with its unknown members) after switching away while the tab section is open.
- **Switching** (`setAuthType`) only changes `type`: the members of the other types stay in the draft, so switching back restores them while the tab is open, and Go leaves them out of the file. Unknown members (`extra`) of an unknown type go and come back with it.
- **Fields:** Bearer has Token, Prefix (shows `Bearer` for the default; clearing it sends the token alone) and "Send this auth"; Basic and Digest have Username, Password and the toggle (Digest's line says the request is sent again with `Authorization: Digest …` once the server challenges it, and that the password itself is never sent); API key has Key, Value, "Add to" (Header or Query params, a native select) and the toggle. Text fields are the single-line `CodeEditor` of the URL bar, so `{{variables}}` are highlighted. A line under the fields says what is sent (`Authorization: Bearer …`) and that an enabled header (or URL parameter) of the same name wins; when disabled it says nothing is sent.
- **JWT** (`JwtFields`, [auth.md](auth.md#jwt-bearer-auth-16)): Algorithm (a native select of the 13 algorithms), "Key from" Typed or File (a local choice, from `keyFile` when the tab opens; going back to Typed clears `keyFile`), then either the secret field (single-line for HS\*, with "Secret is base64-encoded"; for the private-key algorithms a multi-line `CodeEditor`, hidden as a masked box saying how many lines it has) or the key file path (a template field and a Choose… button using the body file dialog, `pickBodyFile`, so a file in the project is stored relative to it); Header and Payload as small JSON `CodeEditor`s; "Add claims" checkboxes (`iat`, `nbf`, `jti`) and the `exp` seconds; "Add to" Header or Query params, the header or parameter name (placeholders `Authorization` and `access_token`) and the prefix. The jwt members live in `AuthDTO.jwt` (`setJwtFields`, filled with `jwtOf`'s defaults on the first edit); the secret is `AuthDTO.secret`. `JwtTools.tsx` adds **Preview token** (not on folders; also under an inherited JWT): `HTTPService.JWTPreview` signs the token of this moment, shown with Copy and Hide, its decoded header and payload and its time claims in UTC; and **Decode a token**, a `<details>` box that decodes a pasted JWT with `lib/jwt.ts` (no verification, nothing saved).
- **OAuth 1.0** (`OAuth1Fields`, [auth.md](auth.md#oauth-10-auth-15)): Signature (a native select: HMAC-SHA1, HMAC-SHA256, RSA-SHA1, PLAINTEXT), Consumer key, Consumer secret (for RSA-SHA1 "Private key", a multi-line masked field, and no Token secret), Access token, Token secret, "Add to" (Authorization header, Query params or Form body), Callback, Verifier, Realm (header only), Nonce and Timestamp (placeholders say they are generated on every send), and checkboxes for `oauth_version=1.0` and `oauth_body_hash`. The members live in `AuthDTO.oauth1` (`setOAuth1Fields`, `oauth1Of`'s defaults on the first edit); the two secrets are `AuthDTO.consumerSecret` and `AuthDTO.tokenSecret`, each a secret field with its own hint and mark (`secretMembers`).
- **AWS Signature** (`AWSFields`, [auth.md](auth.md#aws-signature-v4-auth-17)): Access key, Secret key, Session token (both secret fields, each with its own hint and mark), Region, Service, "Add to" (Authorization header, or Query params for a presigned URL, which shows the expiry in seconds, 3600 by default), and an "Unsigned payload" checkbox. The members live in `AuthDTO.aws` (`setAWSFields`, `awsOf`'s defaults); the secrets are `AuthDTO.secretKey` and `AuthDTO.sessionToken`. The line under the fields names the headers that are added (`X-Amz-Content-Sha256` for `s3`).
- **Hawk** (`HawkFields`, [auth.md](auth.md#hawk-auth-18)): Hawk ID, Hawk key (a secret field), Algorithm (sha256, sha1), Ext, App, Dlg (shown once App is set) and a "Hash the payload" checkbox. The members live in `AuthDTO.hawk` (`setHawkFields`, `hawkOf`'s defaults); the key is `AuthDTO.hawkKey`.
- **OAuth 2.0** (`OAuth2Fields`, [auth.md](auth.md#oauth-20-auth-08-auth-12-auth-33)): Grant type (client credentials, authorization code, password and implicit; a grant of a newer PostSonde is kept, with a warning that sending fails), for the authorization code and implicit grants Authorization URL before the Token URL and Redirect URL after it (placeholder: 127.0.0.1 on a random port, path /callback) with a note that getting a token opens the browser to sign in ([auth.md](auth.md#authorization-code-with-pkce)), Token URL (not for the implicit grant, which has a warning that it is deprecated instead, [auth.md](auth.md#implicit-grant)), Client ID, Client secret (a secret field) and Client authentication (Basic auth header or request body; neither for the implicit grant), for the password grant Username and Password (a secret field, `AuthDTO.password`), Scope, Audience, Resource, State (the redirect grants only), Issuer (OpenID Connect, optional) and the checkbox "Send the ID token instead of the access token" with a note on what is checked ([auth.md](auth.md#oidc-id-token)), Extra parameters (rows of a checkbox, name, value and Remove, then Add parameter; not for the implicit grant), then where the token goes (header name and prefix, or query parameter) as for a JWT. The members live in `AuthDTO.oauth2` (`setOAuth2Fields`, `oauth2Of`'s defaults); the secrets are `AuthDTO.clientSecret` and `AuthDTO.password`. The note says the token is got when the request is sent, kept on this computer, refreshed when it expires and shown in the Timeline tab. Below it, a request (not a folder; also under an inherited oauth2 auth) shows its stored token (`OAuth2TokenPanel` in `OAuth2Tools.tsx`, [auth.md](auth.md#token-store)): none, or the masked token Go sends (the mask and its last four characters) with "valid until" or "expired at" the time and its scope, then, when the token came with an OpenID Connect ID token, its claims (`IdTokenClaims`: the masked ID token and its algorithm, issuer, subject, audience, expiry, name and email, and that its signature is not verified), then **Get new token** (for the authorization code and implicit grants it says "Waiting for the sign-in in the browser…" while the browser is open), **Refresh** (with a refresh token only), **Clear** and, while one runs, **Cancel**; an error is shown under the buttons. The status is asked again 400 ms after the auth changes and on `http:oauth2-token-changed`, and once the token expires. The Timeline tab titles the token request's hops "Token request 1 of 2" and shows the token response's body under its head (`TimelineHopDTO.responseBody`, masked in Go); the send's progress shows "Getting an OAuth 2.0 token".
- **Secret fields** (password, token, API key value, JWT secret, OAuth 1.0 consumer and token secrets, AWS secret key and session token, Hawk key, OAuth 2.0 client secret) are a native password input, or with the eye button the single-line `CodeEditor`. A typed value starts hidden; an empty field or a `{{variable}}` starts shown. The hint under the field follows `secretStorage`: a `{{variable}}` is "saved in the project as a reference", a typed value is "stored only on this computer", an empty field suggests a secret environment variable, and a value marked `localSecrets` but empty (typed on another computer) is a warning. Editing a secret field (`setAuthFields`) removes its own `localSecrets` mark; Go marks it again when the new value is typed. `lib/auth.ts`'s `isTemplateReference` follows `requestsecrets.IsReference` only to pick the hint.
- **Netrc** (`NetrcFields`, [auth.md](auth.md#netrc-auth-19)): File (a template field, `AuthDTO.netrcFile`; empty for the default), a line under it saying which file will be read (`NetrcFileNote`: `HTTPService.NetrcFile`, asked again 250 ms after typing stops; Go resolves the path without reading the file; on a folder a typed path is shown as typed), the toggle, and on requests an **Entry** row with a **Check** button (`NetrcCheck` in `NetrcTools.tsx`, also under an inherited netrc auth): only on a click, `HTTPService.NetrcCheck` reads the file and the row names the matched `machine` (or `default`) entry, its line, the file, its login and whether it has a password, with a warning when others can read the file. The password never reaches the UI.
- **Inherit** shows what the request inherits: `useInheritedAuth` calls `CollectionService.InheritedAuth` when the section shows ("Bearer token, inherited from “Users”", or that no folder sets auth, or the error), then that folder's fields read-only (`InheritedFields`: label and value, `{{references}}` as `TemplateText` chips resolved with the request's variables, the way they are sent; a typed secret, which Go never sends here, as `•••••• stored with “Users”`) and a note that the fields are edited in that folder (AUTH-01, AUTH-32, [auth.md](auth.md#variables-in-auth-fields-auth-32)).
- **Folders:** the [folder settings view](#folder-settings) uses the same editor with `folder` set; only the notes change (what the requests inside send, and that `inherit` passes on the auth of the folder above).
- **Read-only:** radios, select and checkbox disabled, text fields read-only, password inputs read-only, nothing sent; the eye still shows a value.
- **Handshakes** (AUTH-31): the WebSocket, Socket.IO and gRPC editors have an Auth sub-tab with this editor and `protocol` set (`websocket`, `socketio`, `grpc`). `HandshakeNote` warns, before connecting, when the type, the request's own or the one `useInheritedAuth` finds, cannot be sent on that handshake (Digest, OAuth 1.0, AWS Signature, Hawk) or, on gRPC, goes in the query string; on gRPC the line under the fields says the auth is metadata and a Metadata row wins ([auth.md](auth.md#auth-on-every-protocol-auth-31)).
- The Headers tab shows no implicit row for the auth header yet.

## Folder settings

`components/editor/FolderEditor` (COL-03) is a folder's `DIR` tab content: the `DIR` badge, the folder's name and path, a one-line intro, then the sub-tabs **Auth**, **Headers**, **Variables** (counts of enabled, named rows on those two), **Server** (SRV-04, below), **Notes** (COL-07, [Notes](#notes)) and **Run** (RUN-01, the folder runner: `components/runner/FolderRunPanel`, [runner.md](runner.md#ui)), with the request editor's metrics. `TabPanel` mounts it in an `EditHistoryScope` and a panel marked `data-edit-history`, inside a `TemplateVariablesProvider` for the folder's ID.

- **Draft and saving.** A folder's settings are a draft like a request's: `useFolderDraft(id)` (`commands/useRequestDraft.ts`) loads `CollectionService.Folder(id)` with `loadFolderDraft` (`commands/autosave.ts`); the `FolderDTO` has `kind: "folder"`, and the auto-save queue sends such drafts with `updateFolder` instead of `updateRequest`. Everything else is shared: `useAutoSave(id).edit`, the `collection:saved` / `save-failed` events, the status bar, flushing when the tab closes, the undo history (NAV-07, ⌘Z anywhere in the view) and the sub-tab memory in `drafts.subTabs`. Go writes only `auth`, `headers`, `variables` and `description` ([collection.md](collection.md#folder-settings)).
- **Auth** is the [auth editor](#auth-editor) with `folder` set; Inherit shows what the folder inherits from the folders above (`InheritedAuth` takes a folder ID).
- **Headers** and **Variables** are `KeyValueTable`s bound with `useKeyValueRows` (rows keep their `extra`; a secret folder variable's flag rides there as `"secret": true`, read and set by `lib/secretExtra.ts`). Each variable row has a lock button (`aria-pressed`) that makes it secret: its value is then masked (`isValueMasked`) with an eye button to show it, and Go keeps the value only on this computer ([environments.md](environments.md#folder-and-global-secret-variables)); the hint above the table says so. Inherited secret variables arrive without their value and are listed as `••••••` (`data-secret`). The Headers table has the header suggestions. Above each, `InheritedRows` lists read-only what the folders above pass on (`useInheritedSettings`, `commands/folderSettings.ts`, from `CollectionService.InheritedSettings`): name, value and folder, struck through and marked "overridden" when this folder or a nearer one sets the same name (headers ignoring case, variables exactly; `inheritedRows`). A hint says how the rows apply: headers go to every HTTP and GraphQL request inside, a request's own header of the same name winning, then the closest folder's; variables win over the environment's and a subfolder's win over them. On a top-level folder the hint and the table label say **Collection variables** (ENV-03) and spell out the precedence `global < environment < collection < folder`.
- **Chips.** Values are drawn with `{{variable}}` chips resolved for the folder (`HTTPService.Variables(folderId)`: global, environment, the collection and the folders above, then this folder). The provider's `reloadKey` is the draft's `variables`: 300 ms after they change, once the edit reached Go (`waitForQueuedEdits`), the set is loaded again.
- **Read-only.** A folder or project that cannot be written shows a notice with the reason and read-only tables and auth fields; a folder whose `_folder.json` did not load shows Go's error with "Try again" instead of the view.
- **Requests** show the inherited headers in their own Headers tab (see Request editor). Other request editors (WebSocket, gRPC, TCP) do not: folder headers are sent with HTTP and GraphQL requests only.
- **Server** (`components/servers/FolderServerTab`; SRV-04, [servers.md](servers.md#saved-server-configs)) is the folder's saved local server. It is not part of the draft: every change goes to the Go `ServersService`, which writes the folder's `_folder.json` at once, so it is not in the undo history. Without a server it offers the kinds of server (the Servers view's list, `NEW_SERVER_TYPES`) and **Add server** (`createFolderServer`: localhost, any free port, the kind's default configuration, stopped). With one: a status bar (state dot, kind, state, the address to copy, uptime, Start or Stop); **where it listens**, Name, Bind address, Port (empty for any free port) and "Allow connections from other devices (LAN)", each saved when the field is left or on Enter (`updateServerSettings`), locked while the server holds its port ("Stop the server to change where it listens."); a warning whenever the bind address is not loopback (`isBeyondLocalhost`: `""`, `localhost`, `127.0.0.1`, `::1`) or LAN access is on, saying the server will not start until LAN access is allowed, or that other devices can connect; the configuration of its kind, the same editors as the server view: the [routes editor](#routes-editor) for a mock server (in a 460px frame), the WebSocket settings (path, subprotocols, echo as the auto-reply mode, largest message), the webhook response, the SSE settings and timers, the UDP replies (a UDP server has no TLS section), the Socket.IO settings and rules, or the GraphQL mock's schema, generated-data settings and overrides (one panel, `GraphQLMockPanel` with both parts); and **Remove server…** with an inline confirmation. A failed start shows the error and its hint. While this sub-tab is shown, the response pane shows the server's traffic (`App.tsx`, `ServerTraffic`). A saved server Go could not define (an unknown kind, a bad port) shows the problem from the last sync instead (`servers.projectProblems`). Read-only folders show everything disabled.
- Tests: `components/editor/FolderEditor.test.tsx`, `components/servers/FolderServerTab.test.tsx`.

The last sub-tab of every request editor and of the folder view is **Notes** (in the HTTP, SSE and GraphQL editors **Code** follows it, [Snippet panel](#snippet-panel)): the item's `description` as Markdown (TCP, without sub-tabs, has it as a folding section under its options). ## Template variables

`{{variables}}` in the HTTP, GraphQL, SSE, WebSocket and Socket.IO editors (ENV-10, ENV-11, WS-11):

- **Resolved set.** `TabPanel` wraps the HTTP, GraphQL, SSE, WebSocket and Socket.IO editors, and the [folder settings view](#folder-settings) (with `reloadKey`), in `TemplateVariablesProvider` (`components/common/TemplateVariables.tsx`), which loads `HTTPService.Variables(id)` (`lib/templateVariables.ts`; it answers for a request of any kind through `collection.LoadVariablesSource`): every name the request's scopes define, rendered by Go with the chain a send uses, with its value (empty for a secret), whether it resolves and its scope. It loads again on every `environments:changed` event (Go sends it after an environment is created, renamed, deleted, has its variables saved, or another one is made active, and after the global variables are saved), on every `runtimevars:changed` event (a runtime variable set, deleted or cleared, [environments.md](environments.md#runtime-variables)) and when the request moves to another folder. Until the first answer, and when a load fails, nothing is marked red.
- **Code editors.** `components/editor/templateVariables.ts` is a CodeMirror extension: a state field with the set (`setTemplateVariables`), a view plugin that marks every reference found by `lib/templateSyntax.ts` as a `cm-templateVariable` chip (`--tk-var` text on a tint of it), with `cm-templateVariable-unresolved` and `data-unresolved` (`--bad`) when the name is missing from the set or does not resolve (`lookupVariable`: a dynamic value with arguments, `{{$randomInt 1 6}}`, is found by its first word when that is listed with source `dynamic`; Go checks the arguments at send time), and a hover tooltip with the value (`••••••` for a secret) and scope (`Global`, `Environment: dev`, `Collection: API`, `Folder: Admins`; with "· local value" when the value is this computer's local value, SEC-02, `scopeText`), a line naming the lower scopes it overrides (`overridesText`, from the DTO's `overrides`; ENV-06), or why it does not resolve. `templateTitle` (value cells) says the same in one line per reference. Single-line fields (URL, auth fields) always have it; `CodeEditor` adds it to a code editor that mounts inside a provider (body, GraphQL query and variables), not to the response views, and passes the provider's set in whenever it changes (also to a state kept across tab switches). Documents over 100,000 characters are scanned around the visible lines only. A filter pipe (`{{ body | hmacSha256 key }}`, DYN-04) is looked up by `lookupPipe`: red when `lib/templateFilters.ts` (a mirror of Go's pipe parser, run on the same `internal/core/template/testdata/pipes.json` cases) finds an unknown filter or bad arguments, or when its input or a key does not resolve; its hover shows the input's scope and what Go computes at send time, masked when the input or a key is secret.
- **Completion.** Typing inside `{{` opens CodeMirror's completion list (`templateCompletionSource`, logic in `lib/templateCompletion.ts`, the shared popup look of `completionPopup.ts`): the request's variables (scope as the detail, the value, masked when secret, as the info) and then every dynamic value (DYN-01..05, its description as the info); after a `|`, the filters. The source is registered as language data, so the GraphQL and gRPC editors, whose completion overrides it, keep theirs.
- **Response references (DYN-06).** `TemplateVariablesProvider` adds to the set the request's ID and the project's HTTP and GraphQL requests from the collection store (`requests`: ID, name, method and path). `lib/templateResponse.ts` reads `{{$response REQUEST SOURCE EXPR …}}` as Go's `ParseResponse` does (both run `internal/core/template/testdata/responses.json`); `lookupVariable` (`responseVariable`) resolves a valid reference to a known request with its name as the scope (`Response: Log in`) and what it reads as the value, red otherwise (not valid, or no such request). The chip's hover then asks Go for the stored value (`HTTPService.ResponseValue`, never a send; `fillResponseTooltip`, cancelled when the hover closes): the value, masked when secret, the status and age of the response, and whether the next send sends the request first, or why there is none. Completion after `{{$response ` is the request picker: the requests by name, inserting the ID; then the sources; after the expression `send=` and `secret`. The resolution view labels the kind and says when the request is sent first, and reloads on `history:changed`. The stage *Sending a referenced request first* is translated like the others (`httpStageText`). See [templates.md](templates.md#response-references).
- **Tables.** `KeyValueTable` draws value cells with references as chips through `TemplateText` (see KeyValueTable).
- **Resolution view (DBG-08).** The HTTP and SSE editor's **Variables** sub-tab (`ResolutionPanel`, `commands/useResolution.ts`) lists every reference the request uses with the value sent, the scope that wins and every scope that defines it, from `HTTPService.Resolution` ([templates.md](templates.md#resolution-view)); a chip's hover opens it on that name (**Where does it come from?**, `postsonde:show-resolution` from the editor to the `data-resolution-host` around it).
- **Relative URLs (COL-08).** `RelativeUrlHint` under the URL of the HTTP, SSE and GraphQL editors shows where a URL starting with `/` is sent: `{{baseUrl}}` followed by the path, and the scope it comes from ([environments.md](environments.md#base-urls)).
- **Before sending.** Go refuses a request with undefined names with one `template.unresolved` error listing them (`details.names`). `HttpSend.send` (`commands/httpSends.ts`) then asks with `confirm()`: "Send with 2 undefined variables?", naming them, with **Send anyway** and **Cancel**. Send anyway sends again with `allowUnresolved` (the references go out as written); Cancel puts the send slot back as it was before (the previous response stays). Nothing is remembered: the next send asks again. An SSE connect (`SseStream` in `commands/sseStreams.ts`) and a WebSocket connect and send ask the same way (`WsSession` in `commands/wsSessions.ts`, `confirmUnresolved(names, "connect")` words it "Connect with … / Connect anyway"; [websocket.md](websocket.md#variables)).
- **Prompts (DYN-07).** Before that, Go refuses a request with `{{$prompt}}` values it has no answer for with one `template.prompt` error (`details.prompts`, JSON, read by `promptsOf` in `lib/http.ts`). `HttpSend` then calls `askPrompts(fields)` (`commands/prompts.ts`, the same queue pattern as `confirm()`), which `PromptHost` (`components/common/PromptHost.tsx`, mounted by `AppShell`) shows as one dialog: a field per label, filled with its default, a password field when secret, **Send** (a run: **Start**, asked once for the whole run) and **Cancel**. The answers go to `sendHttpRequest`/`repeatHttpRequest` as `prompts` and live only in that send's closure and the dialog's state; Cancel puts the send slot back as it was, like declining "Send anyway". Other request kinds do not ask (a prompt there fails with the error).

## Undo and redo

Every open request has an edit history (NAV-07), kept while its tab is open, across tab and sub-tab switches, and dropped when the tab closes (or its preview tab is replaced, or the request is deleted) and when the request is reloaded from disk. Nothing of it is saved. It works for every editor `TabPanel` shows (HTTP, TCP, WebSocket, gRPC, and any editor added to its `EDITORS` map) without code in the editor, as long as the editor edits through `useAutoSave(id).edit` / `editRequest` and uses the shared `CodeEditor`.

There are two histories per request, and the focus decides which one a key press uses:

- **In a CodeMirror editor** (URL, body, auth fields, message editors), ⌘Z / ⇧⌘Z / ⌘Y (Ctrl+Z, Ctrl+Shift+Z, Ctrl+Y) are that editor's own history (`history()` with `historyKeys`, `components/editor/historyKeys.ts`), with the caret and selection restored. Its change listener sends the result to the draft like typing, so auto-save writes it.
- **Anywhere else in the editor panel** (tables, method picker, selects, check boxes, plain inputs), the same keys walk the request's **draft history**. The key is taken even when there is nothing to undo, so a native input's own undo cannot change a field behind the draft's back. The Undo toast of a delete still takes ⌘Z first while it shows and focus is not in a text field (see Keyboard shortcuts).

**Draft history** (`commands/editHistory.ts`): `editRequest` records every edit as the fields it changed, before and after (fields of the patch whose value did not change are left out). Edits closer than `COALESCE_MS` (1 s) apart that touch overlapping fields merge into one step, so typing in a cell (or in the URL, whose edits also carry `params`) is one step; `editRequest(stores, id, patch, { history: "separate" })` keeps an edit apart on both sides: the method (`setRequestMethod`), body mode and raw type, auth type. At most `MAX_HISTORY` (200) steps; a new edit drops the redo steps. `undoRequestEdit` / `redoRequestEdit` (`commands/undoRedo.ts`) apply a step's `before` / `after` fields with `applyRequestEdit`, the normal draft-edit and auto-save path minus the recording, and dispatch `collection/setMethod` when the method changes, as `setRequestMethod` does. Text-editor edits are recorded too, so ⌘Z in a table also undoes URL typing that came after the table edit: the draft history is one line of every edit of the request. Side stashes (`bodyStash`, `pathParamStash`) and the sub-tab are not part of it.

**Editor states** (`components/editor/editorHistory.tsx`): `TabPanel` wraps the editor in `<EditHistoryScope id>` and marks the panel `data-edit-history={id}`. Inside a scope, a `CodeEditor` that is editable when it mounts keeps its `EditorState` (text, selection, undo history, with the compartments and change listener it was built with) under its `historyKey` when it unmounts, and takes it back when it mounts again; the default key is its `ariaLabel` (and `docKey`, and single-line or not), unique within one request's editor. When the draft changed meanwhile (an undo from a table), the difference is applied as usual, as an undo step of its own (`isolateHistory`). A key already held by a mounted editor is not shared: the second editor starts fresh. `historyKey={null}` opts out.

**Clearing** (`clearEditHistory`): `followEditHistory(stores)` (run by `AppShell` through `useEditHistory`) installs the key listener and drops the history of every request whose draft leaves the drafts store, i.e. whose tab closed. `loadRequestDraft` and `loadFolderDraft` drop it when they replace a clean draft that is already open (a reload from disk after a change outside PostSonde, STO-05), and `takeTheirs` when a draft in conflict takes the file's version ([External changes](#external-changes)). Clearing bumps the request's generation: `EditHistoryScope` remounts the editors inside with fresh states, and a scope from before the clear stores nothing, so an editor unmounting just after its tab closed does not bring an old state back.

## Content Security Policy

The built UI runs under a strict CSP (`frontend/csp.json`): scripts, fonts, images and connections only from the app itself, no inline scripts, no `eval`, and no frames but `about:` ones (the sandboxed HTML preview, HTTP-35). In practice:

- Never load anything remote: bundle fonts, images and libraries. `npm run check:dist` (run by CI after every build) fails on remote URLs in `dist/`.
- No inline `<script>` in `index.html` and no `eval`/`new Function`. Inline styles (`style` props, CodeMirror themes) are fine.
- `wails3 dev` relaxes the policy just enough for Vite's HMR.
- Response content (HTML, SVG) is never put into the app document: it goes into the sandboxed `srcdoc` frame or an `<img>` (`lib/preview.ts`).

Details, the allowlist and the reasoning per directive: [`docs/privacy.md`](privacy.md).

## Accessibility

UI-11: every control can be reached and used with the keyboard, screen readers get roles, names and states, and both built-in themes meet WCAG 2.x AA contrast. The conventions below hold for new code; the tests named with them fail when they break.

**Keyboard**

- **Tab order is document order.** No positive `tabindex`. A control that only the mouse needs (a tab's close button) has `tabIndex={-1}` and `aria-hidden`, and its action has a key (Delete closes a tab).
- **Composite widgets have one Tab stop** (roving tabindex) and arrow keys inside: the collection tree (Up/Down/Left/Right, Home/End, PageUp/PageDown, type-ahead), every tab strip, the key-value grids, menus and listboxes. A tab strip without keys of its own uses `onTabListKeyDown` (`components/common/tabList.ts`) on its `role="tablist"`: Left/Right (Up/Down with `aria-orientation="vertical"`), wrapping, Home/End; selection follows focus, by clicking the tab, so the strip's own `onClick` selects it. The response, SSE, GraphQL subscription, gRPC response, webhook and mock responses strips use it.
- **Escape closes** menus, popups, the autocomplete, the command palette, the quick switcher, the shortcut help and dialogs, and focus goes back to where it was.
- **Modal focus trap only in `Dialog`** (and the command palette and shortcut help, which are Dialogs). Nothing else keeps Tab.
- **Focus is never lost.** Whatever hides the focused element moves focus on: focus mode and closing the settings screen to the work area (`main`, `tabIndex={-1}`), opening the settings screen with ⌘, to its current page (`SettingsScreen`), closing a dialog or menu back to its opener, a closed tab to the next tab.
- **Visible focus.** `base.css` gives `:focus-visible` a 2px `--accent` outline. A stylesheet that removes the outline draws another indicator for the focused state (`box-shadow: var(--focus-ring)`, now a 2px accent ring, a border or a background), or says in an `a11y:` comment why the element needs none (a container focused only from code). `styles/focusStyles.test.ts` checks every stylesheet for this.
- **Tooltips that matter** use `components/common/Tooltip` instead of `title`: it shows on hover and on focus, Escape hides it, and it describes its trigger (`aria-describedby`). The trigger must take focus (`tabIndex={0}` on a non-control). Used by the admin lock (`LockBadge`) and the status bar's "Managed" indicator (`PolicyStatus`), whose disabled controls or clipped text cannot tell a keyboard user why otherwise. Plain `title`s stay for extra detail a visible label already covers.

**Screen readers**

- **Names:** every button, link and field has an accessible name: its text, a `<label>`, `aria-label` (icon-only buttons) or `aria-labelledby`. A placeholder is not a label. Icons are `aria-hidden` unless given a label (`icons.tsx`).
- **Tree:** `role="tree"` with flat `treeitem` rows carrying `aria-level`, `aria-setsize`, `aria-posinset`, `aria-expanded` (folders) and `aria-selected` (see [Collection tree](#collection-tree)).
- **Tabs:** `role="tablist"` (named) holds only its `tab`s; tools beside a strip (view switches, the server name and close button, Add response) are outside it. Each tab has `aria-selected`, the selected one `aria-controls` its `tabpanel`, and the panel is `aria-labelledby` the tab.
- **Tables:** key-value editors are ARIA grids with column headers ([KeyValueTable](#keyvaluetable)); read-only data are `<table>`s with `<th>`.
- **Live regions:** toasts are a polite live region ([Toasts](#toasts)); status lines use `role="status"`; errors next to what failed use `role="alert"` (assertive).
- **Dialogs:** `role="dialog"`, `aria-modal`, named by their title (see [Dialog](#dialog)); everything else is `inert` while one is open.

**Contrast**

- Text tokens (`--text`, `--text2`, `--text3`, the method, status, accent and syntax colours) reach 4.5:1 on the surfaces they are drawn on; `--accent` reaches 3:1 as a focus ring, focused border or selected tab underline on every surface. `--line`/`--line2` (dividers) and `--scrim` are decorative and not checked; fields are identified by their label and background, not their border.
- `styles/contrast.ts` lists the pairs (`CONTRAST_RULES`): text on `bg0`–`bg3`, the selection (`--sel` over `bg0` and `bg1`) and, except muted text, the accent tint; coloured text on `bg0`–`bg2` and the selection; syntax colours on `bg0`–`bg2` and the selection; `--accent-ink` on `--accent`. `styles/contrast.test.ts` reads `tokens.css` and checks both themes. A new token or a new pairing gets a rule there.
- Custom themes (UI-05) are the user's files and are never refused for contrast: the settings screen lists the pairs a chosen theme breaks, worst first, where the theme set one of the two colours (`styles/themeContrast.ts`).

**Tests**

- `test/a11y.ts` is a small audit for jsdom, no axe-core: `auditA11y(root)` returns violations, `expectAccessible(root)` fails the test with them. Rules: an accessible name for every control and named role (and a placeholder alone is flagged), no positive `tabindex`, `aria-*` id references and `label for` point at existing ids, no duplicate ids, valid roles, required context and children (a `tab` in a `tablist` holding only tabs, `treeitem` in a `tree`, `option` in a `listbox`, rows and cells), exactly one Tab stop per tab list and tree, `aria-selected` on tabs and tree items, tab panels labelled by their tab, no Tab stop inside `aria-hidden` or inside another control. It also has `pressTab()`/`tabTo()` (jsdom has no Tab key: they move focus through the Tab stops as a browser would, unless a handler prevented the key, such as the Dialog's trap) and `accessibleName()`.
- `components/a11y.test.tsx` renders the app shell as `App` does for an open project, with Go faked, and audits the shell, tree, tab bar, every request sub-tab, every response section, the tree's context menu, the history view with its filters and an entry's context menu, every settings page, the New request dialog, the command palette, the quick switcher, the shortcut help, and the details and traffic of each kind of server (mock HTTP, WebSocket, TCP, UDP, SSE, webhook, gRPC mock). It checks what the tree and the tab strips tell a screen reader, and runs the core flows with keys only: create a request (⌘N), Tab to the URL and type it, send (⌘↩), Tab to the response and arrow through its sections; walk the tree (arrows, type-ahead, Enter), switch tabs and sub-tabs with arrows; open the settings (⌘,), change page and come back (⌘B); run a command from the palette; Tab stays in a dialog.
- Not covered by tests: how a real screen reader speaks the app (VoiceOver, NVDA, Orca), visible focus rings as rendered, and contrast of text over images or gradients. Check those by hand when a screen changes.

## Localization

UI-10: every text the UI shows comes from a message catalogue through `t()`, so the app can be translated. English is the only real language; a generated test language (the pseudo-locale) shows what is not translatable yet. The code is in `src/i18n/`, no library: typed keys, `{name}` placeholders, plurals with `Intl.PluralRules`, and formatting with `Intl`.

```
src/i18n/
  index.ts        the barrel, no React: t, tParts, setLocale, formatNumber/Date/RelativeTime, LOCALES, errorText
  react.ts        useT(), useLocale(), <Trans>
  catalog.ts      the English catalogue: one namespace per area, the key and parameter types
  messages.ts     the message format and its types (placeholders, plural messages)
  format.ts       formatting one message: plural form, placeholders
  locale.ts       the language in use, t(), locales and "system", formatters
  pseudo.ts       the pseudo-locale, generated from the English catalogue
  en/<ns>.ts      English messages, one module per namespace; en/errors.ts: Go error codes (empty)
  allowlist/      files not converted yet, with their counts (the check below; empty now, created again by i18n:update if needed)
```

**Namespaces.** A key is `"<namespace>.<id>"`: `t("shell.statusBar.ready")`. There is one namespace per area of the source, named like the area of the check below: `components/<folder>/` has `<folder>` (`shell`, `settings`, `common`, `editor`, `servers`, …), `commands/` has `commands`, `lib/` has `lib`, `src/App.tsx`, `main.tsx` and the files directly in `components/` have `app`. Each is its own module, `en/<namespace>.ts`, already listed in `catalog.ts`, so areas are converted in parallel without touching the same file: an area adds messages to its own namespace only. It may use another's (`common.ok`, `common.cancel`, `common.theme.dark`) but does not add to it; a message needed by two areas goes into each, or into `common` in a change of its own. Ids are dotted camelCase, component or feature first: `"titleBar.closeProject"`, `"dataDir.pending.move"`.

**Adding a string:**

1. Add it to the area's module:
   ```ts
   export default {
     "statusBar.ready": "Ready",
     "titleBar.theme.switch": "Theme: {theme}. Switch to {next}",
     "autosave.failed": { one: "Save failed", other: "{count} saves failed" },
   } as const satisfies Messages;
   ```
   Keep `as const`: it is what lets TypeScript know each message's placeholders.
2. Show it with `t()`. A component takes it from `useT()`, which re-renders it when the language changes; other code imports `t` from `i18n`:
   ```tsx
   const t = useT();
   return <footer aria-label={t("shell.statusBar.label")}>{t("shell.statusBar.ready")}</footer>;
   ```
   ```ts
   showToast({ message: t("shell.palette.declined", { command: def.label }) });
   ```
   `tsc` checks that the key exists and that every placeholder gets a value, no more (`src/i18n/types.test.ts`).
3. Tests keep asserting the English text: the catalogue is English.

**Rules:**

- **Never call `t()` at module level**: the text would be fixed in the language of the moment the module loaded. Tables of labels hold keys (`labelKey: "shell.view.history"` typed `MessageKey`) and call `t(labelKey)` where they are shown. The check fails on a module-level `t()`.
- **Whole sentences, with placeholders**, never glued pieces (`"Deleted " + name`): other languages order words differently. `{name}` is a letter/digit/`_` name; `{{…}}` is text (the `{{variable}}` syntax of requests), so `"insert with {{$file PATH}}"` needs no escaping. A missing parameter shows as `{name}`.
- **Plurals** are objects keyed by the `Intl.PluralRules` categories (`zero`, `one`, `two`, `few`, `many`, `other`; `other` required) and exact counts (`"=0": "No requests"`), picked by the `count` parameter, which `t()` requires. English needs `one` and `other`; another language adds its own categories.
- **Numbers** in placeholders are written with the locale's digits and decimal sign, without grouping (ports, years, sizes stay `8080`). For grouped numbers, dates and relative times use `formatNumber`, `formatDate` and `formatRelativeTime` from `i18n`: they follow the language in use.
- **Markup in a sentence** (`<code>`, a link, a path in its own style): `<Trans k="settings.dataDir.deleteBody" values={{ folder: <span className={…}>{path}</span> }} />` (built on `tParts`).
- **Not text:** names (fonts, the brand), protocol tokens (`GET`, `Content-Type`), file names and code samples stay as they are. The check skips obvious ones; mark the others with an `i18n-ignore` comment saying why (below).
- **Memoised values:** the `t` of `useT()` changes identity with the language, so a `useMemo`/`useCallback` that uses it lists it as a dependency. A `memo` component that shows text calls `useT()` itself (as `Markdown` does).

**The language setting** is `ui.locale` in `settings.json` ([settings.md](settings.md)): `"system"` (default) or a language tag. Settings → General → Appearance → Language. `components/shell/useLocaleSync` (called by `App`) applies it live with `setLocale`, whoever changed it (the screen, a hand edit, the admin policy), sets `<html lang>`, and caches it in `localStorage` (`postsonde.locale`) so `main.tsx` starts in the right language before the settings file has loaded. `"system"` takes the first of the web view's languages (`navigator.languages`) the app has, by tag or by language (`en-GB` → `en`), else English, and follows `languagechange`. A tag the app has no messages for is kept (a newer build may have them) and English is shown; the screen lists it as "(not available, English is shown)".

**The pseudo-locale** (`en-XA`) is every English message accented, about 30% longer and in brackets: `"Send request"` becomes `"[Šéñð ŕéǫûéšţ one]"`. It is generated from the English catalogue when it is selected (`pseudo.ts`), never written by hand, so it always has every message. With it on, English text on screen did not come from the catalogue, and text that is cut off or overflows will be with a real translation. It is listed under Language only in dev builds (`wails3 dev`, `npm run dev`, `build:dev`, and tests); in any build, `"ui": {"locale": "en-XA"}` in `settings.json` turns it on (it is then listed too). It is never picked for `"system"`.

**Errors from Go.** Error messages and hints come from Go (`errs`, [errors.md](errors.md)) and stay English there: logs, the console and Go's tests read them, and Go has no language setting. The UI localizes them by code: `toAppError` (`lib/errors.ts`), the one place every Go error passes, asks `errorText(code, …)`, which returns the message of the language in use for `"<code>"` (and `"<code>.hint"`) with the error's `details` as placeholders, and Go's English text when there is none. `en/errors.ts` stays empty because Go's text is the English; a translation adds the codes it translates, in any order and at any time. Until then, errors are English in every language, and so in the pseudo-locale, which is correct: they are not translated yet. Messages the UI makes up for errors (`errorTitle`, the cancelled and internal fallbacks) are in the catalogue (`lib.errors.*`).

**The check for hard-coded strings.** `scripts/i18n-strings.mjs` parses every `.ts`/`.tsx` file under `src/` (not tests, `src/test/`, `src/i18n/`) with the TypeScript compiler API and reports UI text not going through `t()`: JSX text; strings in UI attributes (`aria-label`, `title`, `placeholder`, `alt`, `label`, and any `…Label`, `…Title`, `…Text`, `…Message`, `…Hint`, `…Placeholder`, … prop); strings as JSX children (`{busy ? "Saving…" : "Save"}`); UI properties of objects (`showToast({ message })`, `confirm({ title, confirmLabel })`, `{ label }`); `set…Error`/`…Message`/`…Status`/`…Text` setters; and sentence-like strings wherever a value goes (a variable, a return, a property, an array, an argument). It skips strings without letters, single code-like tokens (`settings.json`, `Content-Type`, `PostSonde`, `GET`, message keys), and what is inside `<pre>` and `<code>`. A line with an `// i18n-ignore: <why>` comment, or the line after one, is skipped; so are the lines between `// i18n-ignore-start` and `// i18n-ignore-end`, and a file with `// i18n-ignore-file: <why>`.

- `npm test` runs it (`scripts/i18n-strings.test.mjs`), so `scripts/check-frontend.sh` and CI fail when a file has **more** hard-coded strings than its allowlist entry, or any without one, and on a module-level `t()`.
- **The allowlist** is `src/i18n/allowlist/<area>.json`, one file per area (`components-editor.json`: `{ "components/editor/AuthEditor.tsx": 261, … }`): the files not converted yet and their counts. Fewer strings than allowed passes, with a note. After converting, `npm run i18n:update` rewrites the counts (and drops converted files and empty areas); commit the result with the conversion. Each area has its own file, so parallel conversions do not conflict.
- `npm run i18n:report` prints the count per area and file; `node scripts/i18n-strings.mjs --list` every string with its line.

**The pseudo-locale test.** `src/i18n/pseudoLocale.test.tsx` renders the converted part of the UI in the pseudo-locale and checks with `test/pseudoLocale.ts` that pseudo strings show and that no English text of the converted namespaces is left (`englishLeftovers`: a text equal to a fragment of one of their English messages, or containing a long one). Every area is converted: the allowlist is empty (the directory is gone), so any new hard-coded string fails the check. Each area also has its own pseudo-locale test next to its components: `i18n/pseudoLocale.test.tsx` (the app shell, every settings page, `Dialog`, `confirm()`, toasts and `Tooltip`; namespaces `shell`, `settings`, `common` and `lib.errors.*`), `components/editor/editor.pseudo.test.tsx` (the request editor, `editor`), `components/editor/protocols.pseudo.test.tsx` (the gRPC, GraphQL, WebSocket, Socket.IO and TCP editors, `editorProtocols`), `components/response/response.pseudo.test.tsx` (the response panels and the message log, `response` and `messagelog`), `components/servers/servers.pseudo.test.tsx` (`servers`), `components/runner/FolderRunPanel.test.tsx` (the folder runner, `runner`), `components/history/HistoryPanel.test.tsx` (the history panel, `history`), `components/tree/tree.pseudo.test.tsx` (the tree, Import dialog, environments, cookies, console and tabs) and `commands/palette.pseudo.test.tsx` (the shortcut registry's text, `lib` and `commands`: the command palette and Settings → Shortcuts). Text from Go (error messages and hints) stays English until a locale adds messages for its error codes; see [errors.md](errors.md).

**Converting an area:**

1. `npm run i18n:report` (or `--list`) for the area's files and strings.
2. Move each string into `en/<namespace>.ts` and use `t()` / `useT()` as above; keys for tables of labels; `i18n-ignore` for what is not text.
3. `npm run i18n:update`; the area's allowlist file shrinks or goes.
4. Add the namespace to `CONVERTED` in `src/i18n/pseudoLocale.test.tsx`, render the area's screens there (or in the area's own test with the helpers of `test/pseudoLocale.ts`), and remove its entries from the test's `foreignElements` and `FOREIGN` lists.
5. Tests keep asserting English.

**Adding a locale:** add `src/i18n/<tag>/<namespace>.ts` modules typed `Translation[namespace]` (any subset: a missing message falls back to English, message by message), an `index.ts` that puts them together as a `Translation`, optionally an errors module (`ErrorMessages`, by Go error code), and an entry in `LOCALES` (`locale.ts`): `tag`, `name` (in the language itself), `intl` (the locale Intl uses), `messages`, `errors`. Plural messages use the language's own categories. Nothing changes in Go: `ui.locale` accepts any language tag. `registerLocale` adds one at run time (tests).

## Naming

| Kind | Convention | Example |
|---|---|---|
| Component | PascalCase `.tsx`, one exported component per file, named export | `components/tabs/TabBar.tsx` exports `TabBar` |
| Component styles | CSS Module next to the component, using the tokens from `styles/tokens.css` | `TabBar.module.css` |
| Hook | `useThing` in `useThing.ts` | `useSelector.ts` |
| Store module | lowercase noun | `stores/tabs.ts` |
| Store exports | `<Name>State`, `initial<Name>State`, `<Name>Action`, `<name>Reducer`, `select<Thing>` | `TabsState`, `tabsReducer`, `selectIsPinned` |
| Action type | `"<store>/<verb>"`, verb in camelCase, flat payload fields | `{ type: "tabs/setPinned", id, pinned }` |
| Command | verb phrase, `stores` first | `openRequest(stores, id)` |
| Ids | `NodeId` strings; fields named `xxxId` / `xxxIds` | `activeId`, `childIds` |
| Test | next to the file, `.test.ts` or `.test.tsx` | `stores/tabs.test.ts` |

`App.tsx` keeps its default export from the scaffold; everything else uses named exports. Global CSS lives only in `styles/`.
